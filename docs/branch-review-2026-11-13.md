## 实质发现（静态审查，针对固定版本）

以下中英文文件对应行号一致，均指PR #6 `b26a2c1`。未发现需要P1级处置的工程问题。

1. **P2：理想路由并未构成所声称的上界。** `docs/dynamic-skill-loading-experiment-plan.zh-CN.md:149`只给金标技能“类别”，不是完整、可执行的所需技能集合。多技能任务仍可能遗漏必要技能，不能将这个对照与Flat的差用于宣称最大可得收益（L160–161）。应定义逐轮所需技能集合，保留同样权限／证据／执行器，并把oracle称为诊断参考；在确认参考有效且差异有明确正值前不计算η或用其否决动态加载。
2. **P2：功效数字缺少推导。** 同文件`:157`直接称300任务×4次可检出5–7个百分点。pass^4的独立单位仍是任务；结论取决于基线、配对不一致率、任务相关性、alpha、power及多重比较。应删去保证式表述，先用pilot估参数，给出任务级配对模拟／功效计算；四次重复不能当1200独立任务。
3. **P2：过采样缺少总体风险还原。** 同文件`:140`过采样易混对和目标切换，却未定义自然流量校准／测试集或抽样权重；若据此估升级量、成本或选择阈值，会改变部署工作点。需独立自然流量留出用于业务验收，压力集单报；训练／开发／校准／测试按会话和时间拆分，困难样本富集不能直接当总体风险。
4. **P2：结论表不足以支持采用及根因归因。** 同文件`:196`以H2、oracle收益及η判采用，未直接要求实际Routed相对Flat的风险、净成本、置信区间达到验收；`:199`把所有loader未达recall阈值归因为粒度。应将实际方案的预定成功／违规／完整成本约束作为采用门槛；未达标先分辨标签、证据、模型、候选与粒度，避免由失败结果直接指定根因。`:203`的“零成本”也应改为无新增模型调用，计入取状态与维护成本。

PR #5的主要风险是版本集成而非把计划写成结果：当前文本已经显式区分数学最优风险差与有限模型损失、独立组划分、未测硬件容量、研究新颖性未成立和停止规则。此次静态检查未发现比上述问题更明确的新P2；这不认证其全部引用、训练配方或研究创新。
