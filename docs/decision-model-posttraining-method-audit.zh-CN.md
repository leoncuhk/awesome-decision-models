核查日期：2026-11-19。对象是TypeSafe Jev式有界概率判断，不是JEPA、交易策略或泛指Agent RL。本文核查用户提供材料中的方法、数字与推论，供[企业后训练主线](decision-model-posttraining-enterprise.zh-CN.md)使用。证据为论文正文、表格、版本历史及作者代码说明；没有执行训练、推理或独立重标注，所有外部成绩均为作者报告。

## 2. 需要修正的关键说法

| 原说法 | 判定 | 应怎样表述 |
|---|---|---|
| “官方RLCD没公开，所以RLCD用不上” | 混淆对象 | 当前公开材料不能还原TypeSafe内部算法；可研究和运行独立的OpenJev-RLCD/PRDO实现，不能称其复现了Jev内部配方。[v1](https://arxiv.org/html/2609.38850v1)、[v2](https://arxiv.org/html/2609.38850v2) |
| “客服读证据任务CE已经够了，RL不会更好” | 外推过度 | CE＋独立校准应是强基线。现有研究限定任务、模型、奖励及预算，不能证明所有客服任务上RL均无益；更不能把开放域推理增益直接移植到客服。[CAPS §4.2](https://arxiv.org/html/2611.15572v1#S4.SS2)、[PRDO §5](https://arxiv.org/html/2609.38850v2#S5) |
| “RLCD期望梯度等于直接Brier，所以等于换损失” | 有条件成立 | 无随机推理/动作路径、完整外生标签、直接对输出分布的proper score求导时，可写成监督损失。有参数依赖的随机推理时，路径梯度与score-function梯度须分开；不同损失也不保证有限模型、样本和优化下等效。[v1 §2–3、5.3–5.4](https://arxiv.org/html/2609.38850v1) |
| “损失比较使用Qwen3.5-4B、输出头冻结” | 读反了 | 附录F比较的是**冻结主干、训练其上的输出头**。该早期设置也不能与主文LoRA结果直接拼表。[Inner Jev附录F、表16](https://arxiv.org/html/2610.17205v1#A6) |
| “base70.3比instruct84.4低14.1，故都应选对话版” | 指标与范围缺失 | 这是Gemma 4 31B、该配方下的OpenDecisions **Capability**消融，不是Qwen准确率，也不是所有底座的定理。实际底座应同任务、同输入/训练预算比较。[表5](https://arxiv.org/html/2610.17205v1#S5.T5) |
| “约400步就停” | 不能作为通用规则 | 该配方每步65,536 padded tokens，400步约76,000题；步骤数不能脱离tokens、更新量、数据重复和学习率日程。训练长度表中部分800步或更长点估计更高；应由开发集和预算选checkpoint。[附录B、表9](https://arxiv.org/html/2610.17205v1#A2) |
| “温度不能小于1” | 把局部措施当通则 | T只需为正。该论文因校准分布迁移而把T截到1，属于自己的保守选择；欠自信模型可需要T<1。正T不改变同题argmax，可能改变跨题置信排序或ordinal期望分。[附录G](https://arxiv.org/html/2610.17205v1#A7)、[Guo等](https://proceedings.mlr.press/v70/guo17a.html) |
| “不到1个百分点基本可以看作噪声” | 统计错误 | 看配对差值区间、独立案件数、种子差异和预定最小有用差异，不能设统一1pp界线。未显著不是等价，罕见高损失错误的小变化也可能重要。[统计口径](methodology.md#direct-comparison-is-conditional) |
| “土耳其语REINFORCE准确率掉10.2点” | 指标错误 | 原文为**macro-F1下降10.2pp**，具体为以目标在采样答案上的概率为奖励的REINFORCE；并非所有proper-score/RL训练。[表4](https://arxiv.org/html/2610.06744v1#S7.T4) |
| “教师给概率，便能直接教会真实校准” | 缺少真值条件 | 蒸馏首先拟合教师分布；教师的偏差、候选条件和失准也会传递。教师一致率、logit分布和模型口述置信度都不是自动成立的事件概率，仍需独立金标与目标流量检验。[SII §6](https://arxiv.org/html/2610.03935v2#S6) |
| “信息不足就给均匀目标” | 可用的正则，不是事实 | 均匀分布表达等质量假设，不能自动区分缺信息、候选遗漏、多条路径均合法、无适用路径和事实冲突。企业标签应显式记录这些情况，单独验拒判、补证和回退；不把人为摊平当真实概率。[方法边界](methodology.md#interpret-scores-before-acting) |
| “历史最终处理结果可直接当当前决策标签” | 需逐案核验 | 最终归属、人工修正和结局可能依赖未来信息与干预；必须恢复当时可见证据，并核对候选是否可用及标签是否唯一。真实业务成功不是必然的单类正确性指示变量。[CAPS局限](https://arxiv.org/html/2611.15572v1#S5) |
| “这个领域2026年9月才出现” | 命名与方法混淆 | Jev及当轮产品发布可按各自日期记载；概率预测、分类、proper scoring、选择性预测与校准已有长期研究，不以新品日期定义方法起源。[Guo等，2017](https://proceedings.mlr.press/v70/guo17a.html) |

“期望梯度相同”只有在明确随机变量与求导路径后才有含义。例如对随机推理`r ~ πθ`，`∇E[S]`一般同时含`E[∇S]`和`E[S∇log πθ]`；去掉后者或冻结采样路径，改变的是估计目标/优化方式。另一方面，proper loss以真实条件分布为最优点，不保证一个受限模型在有限数据上的优化、判别和校准均相同。以上是对论文设定的解释，不声称给出新理论。

## 3. 可使用的横向结果，按协议分开

### 3.1 冻结主干的损失比较

[Inner Jev附录F表16](https://arxiv.org/html/2610.17205v1#A6.T16)的Qwen3.5-4B早期头部实验；相同七组外部决策任务，macro accuracy，ECE原始/温度校准后：

| 损失 | 准确率% | ECE原始 / 校准后 | 训练种子数 |
|---|---:|---:|---:|
| CE | 78.5 | .092 / .092 | 3 |
| Brier | 79.6 | .093 / .094 | 1 |
| Focal | 76.3 | .193 / .099 | 1 |
| CE＋MMCE，λ=2 | 78.8 | .086 / .086 | 1 |
| Expected utility，r=3 | 79.4 | .076 / .094 | 3 |

这些点估计支持把CE保留为强基线，没有建立“Brier更强”或“RL必然无益”。选择损失、校准策略与模型时均有开发选择因素；不得把各列最好数字再拼成一个不存在的方案。

### 3.2 RLCD旧版与最新PRDO

v1表1中，Qwen3-1.7B GSM8K-Verify的SFT准确率70.4%、GRPO91.8%、两阶段RLCD92.2%，以及测试oracle coverage@5%的19.4%与81.1%，数字确有出处。SFT直接答，RLCD有推理且训练400＋400步；coverage用测试标签取满足错误预算的最大前缀，不能当上线门槛验证。去KL约100步退化对应从头端到端实验，第二阶段去KL约330步退化是另一实验。

**当前判断改用[v2 PRDO](https://arxiv.org/html/2609.38850v2#S5)**：它对每条采样推理后的读出施加proper score，路径求导＋token KL，不要求奖励推理；最新对照统一400更新步、同问题和结果流。Qwen3-1.7B在重新隔离的1,000题MMLU-Pro最终测试上：

| 方法 | 准确率% | Brier↓ | AURC↓ |
|---|---:|---:|---:|
| 直接SFT＋TS | 39.5 | .710 | .383 |
| GRPO＋TS | 41.8 | .750 | .472 |
| PRDO-Brier | 44.4 | .670 | .317 |

三种子均值；这仍不是相同推理token成本。四底座MMLU-Pro方向一致，但验证任务有边界：0.6B的选择性排序变好、总体准确率反而下降；1.7B未发现差异。增加第二阶段未测出可靠增益。v2另用独立校准集、预固定阈值网格及错误上界做risk control，和其测试oracle coverage明确分开；不把v1的大覆盖率数字用于代表v2或企业收益。

### 3.3 部分反馈：CAPS能支持到哪里

[CAPS表1](https://arxiv.org/html/2611.15572v1#S4.T1)，Banking77，0.6B，N=5,000：

| 方法 | 准确率 | ECE | AURC |
|---|---:|---:|---:|
| 仅确认正确的记录SFT | .905 | .078 | .0202 |
| CAPS-Brier | .931 | .025 | .0107 |
| 完整标签SFT | .946 | .022 | .0067 |

前者只有一个训练种子，后两者三种子。所贴+2.6pp、ECE−.053正确，但论文的日志由真实类别金标**模拟**：已知epsilon logger、有支持的采样动作、已知/干净或对称翻转的反馈。它没有验证真实“转人工后解决”“退款被申诉”的因果归因，也没有做部署政策的反事实价值估计。完整标签实验仅支持“四个未见schema的平均ECE未超越CE＋TS”，不是所有指标、场景上的不可能性定理。

实际客服中，多动作均可成功、负反馈迟到/缺失、只记录人工接管等会破坏该设定。先核反馈代表何种事件、时窗、干预与支持；未知反馈不能直接标0，归一化单类概率也不能直接等同每条合法路径的成功概率。

### 3.4 JEVal与自蒸馏

[JEVal v2表1](https://arxiv.org/html/2610.03935v2#S4.T1)中Jev78.38/.0532、SII-Decision-27B79.24/.0149、Kev-27B77.17/.0356、Intern-Decision-4B70.74/.0152、Laya26.30/.2485（准确率%/ECE）可确认。总集11,257题含9,457英语与1,800中文，但该准确率表只覆盖**10,938个choice/noul**；ECE/Brier只算有效输出，准确率把无效输出计错。Laya是该实验所用版本与输入预算，不能代表当前多语种微调候选在企业上的上限。

SII使用同模型两条推理的候选logit分布平均作为目标，不用人工gold筛选或替换；27B扩至39,279题。目标函数有soft CE、score项和原模型KL锚定，full-rank/LoRA是不同实现，不是普通正确答案SFT，也不是RL。它压缩了部分候选权衡，计算密集推理能力不能全压入一步。论文τ-bench替换动作选择器后总体成功77.6%→66.1%，中位更快、p95更慢；这是一组任务每题一次的作者实验，不能泛指任何决策器都会降低多轮成功。

### 3.5 相邻证据：RLCR与土耳其语消融

[RLCR正式论文](https://openreview.net/pdf?id=ASQ649zdHm)的HotpotQA62.1%/.03对RLVR63.0%/.37（准确率/ECE）有原表支持；它生成答案、分析和显式置信度，非无文字单步判断头，不能混入同一速度/成本排名。其研究早于Jev发布，也说明校准奖励不是新品才出现。

[土耳其语论文表4](https://arxiv.org/html/2610.06744v1#S7.T4)确实报告特定REINFORCE比CE损失macro-F1；其奖励对概率是线性的，趋向单一模式，不代表优化分布的全部RL方法。该模型多轮研发读过测试结果、人工标注主要来自一人，主要用于揭示失败模式，不作为中文方法选优依据。

## 4. 对企业后训练选型的影响

1. **完整、可靠标签**：先比较不训练的强读出/小分类器与监督CE；Brier、soft CE及校准是独立可调因素。底座与可训练模块按代表性最长输入和中文切片实测，不能固定“400步”“4B拐点”或“只训头无效”。
2. **教师或自蒸馏标签**：单列训练成本、教师重复一致性和人工裁定差异；评价由独立gold/业务终态承担，避免用同一教师自证。
3. **需要计算的推理判断**：保留生成式强基线和PRDO类候选，匹配训练/推理预算、退化与迁移；先测是否值得承担推理成本，不因RLCD名称先上强化学习。
4. **仅选中动作的反馈**：CAPS可作有条件研究候选。先审计日志事件与标签的关系、选择偏差、支持和缺失；政策优化和业务增量需要另外的识别/实验合同。
5. **拒判与上线**：在目标流量的独立校准组确定完整策略，再在冻结测试/影子流量检查错误、覆盖、返工、尾延迟和完整成本。分布偏移后重新确认；模型选了“NONE”不等于得到风险保证。

## 5. 复现与尚未执行的边界

论文全文核查不等于产物完整审计。PRDO[作者仓库](https://github.com/ZimmyGao/openjev-rlcd)当前HEAD为`5859d2b893314fb3581f06e4e36c303e372b3f48`；README描述`arxiv-v1`与`npj-experiments`两个tag，本次GitHub tags API及`git ls-remote --tags`都未返回tag，故不能把这些名称写成已成功解析的运行pin。真正复现前还需核对论文数据存档、每次run的代码版本和split哈希；当前默认分支存在训练代码不代表论文全部结果已在本地重建。

本轮未下载权重、安装训练依赖、执行模型、核验原始企业数据或生产指标；没有新增`reproduced_here`记录。上述比较用于提出可证伪候选和纠正过度结论，最终方法取决于未来企业的决策合同与独立数据。

## 6. Laya低分与此前优先建议：独立补核

2026-11-19补核直接追查论文、公开数据、当前模型配置和已发布代码。**Mac训练入口可用不能推出效果优先；当前证据不足以把Laya列为企业客服后训练的默认首选。** JEVal中的低分必须保留，不能用未经验证的“语言／截断问题”替它解释。

| 核查项 | 已确认 | 尚不能确认／对应结论 |
|---|---|---|
| 26.30%的口径 | [JEVal v2表1](https://arxiv.org/html/2610.03935v2#S4.T1)按10,938个choice/noul合并计数，失败计错；ECE .2485与raw Brier .833只算有效输出。NanoJev为25.34%，所以Laya处于低端但非严格最低 | 不是企业客服专用分数，不是微调后增益；不能与另一任务的作者微调成绩直接相减 |
| 实际上下文预算 | [附录C.3／表9](https://arxiv.org/html/2610.03935v2#A3.SS3)明确把Laya从512提高至8,192，位置配置不改，保留48-token选项上限 | “因为评测只给512 tokens才低分”与论文说明矛盾。是否截掉关键证据／选项碰撞导致错误，缺逐题产物不能归因 |
| 哪个Laya | 论文只写Laya和上游GitHub链接。其温度组合与[当前English配置](https://huggingface.co/convaiinnovations/laya/blob/e333cb7c823cd1787276228260f56d02fbf5180b/rl_agent_config.json)一致；[multilingual配置](https://huggingface.co/convaiinnovations/laya-multilingual/blob/92d22143468d8af669dc1a5a0480a2b21b4fe56e/rl_agent_config.json)则为全1温度、不同encoder | 这是English家族的配置指纹线索，不是论文实际权重ID／revision证明；当前配置不能倒填历史run。HF revision、PyPI版本、adapter和run manifest未公开固定 |
| 原始预测与评测器 | [JEVal固定数据说明](https://huggingface.co/datasets/carlosxiang/JEVal/blob/5d0253c34cf5e371b3ae99c21f0a7170d7289f63/README.md)明确公开的是输入与标签，不含逐请求预测。[SII代码树1723d83](https://github.com/amazingljy1206/SII-Decision/tree/1723d83cbda69f48641c273280b5a2d06d6b3510)有SII训练／推理／验证，没有本次定位到的Laya adapter及原始run | 无法本地重算26.30、核分模型失败数或认证native／wrapper等价；网页、论文和同作者数据卡重复同一数字，不算三次独立复现 |

另实际读取了公开`test.parquet`的固定版本`5d0253c34cf5e371b3ae99c21f0a7170d7289f63`（33,533,925 bytes；SHA-256 `88f090a510e511d1236fdf5ddb428a8b965663ff0cc1061f950b88f0c99d2e82`），只复算输入元数据，没有运行模型。确认11,257行＝9,582 choice＋1,356 noul＋319 score；其中3,297条分类指令含汉字，1,497条同时具有“指令含汉字、state无汉字”；2,294条choice超过20选项，最高255。这里“含汉字”是Unicode范围计数，不是语言识别或失败原因鉴定。

**这些输入差异不能推翻低分。** 对CLINC150和NLU-Eval-68各200条，实际state、instruction、criteria均未检出汉字，论文仍报告Laya准确率39.0%和27.0%，而Jev为86.5%和80.5%；[对应表10–11](https://arxiv.org/html/2610.03935v2#A4.SS1)使“差距全由中文造成”站不住脚。另一方面，同表BoolQ的Laya为79.5%，表现随任务变化，不能以26.30%认定它在所有二元证据判断上都无效。大候选集合、输入预算和语言是需要分切片验证的条件，不是已证实的免责解释。

据此应区分三个待验证命题：现成检查点的零样本能力、特定标注预算下的后训练增益、目标系统的净业务收益。JEVal直接约束第一项；它没有提供同数据、同预算的Laya／其他底座后训练比较。较小模型的训练接口和内存优势只支持把它作为可运行的低成本实验对照；是否进入生产候选，须先在相同状态、候选与中文切片上通过质量门槛，再比较标签效率、风险—覆盖与完整成本。缺少这一证据时，不能用“经过微调也许会更好”恢复默认优先级。

## 8. PRDO v2全文复核：怎样改变当前路线

本节重新读取[论文v2全文](https://arxiv.org/html/2609.38850v2)（正文1–7、附录A–G、图注及补充表1–6），并静态读取[作者代码5859d2b](https://github.com/ZimmyGao/openjev-rlcd/tree/5859d2b893314fb3581f06e4e36c303e372b3f48)的训练器、估计器、offload、指标、评估和实验计划。**结论是：PRDO值得作为“推理后判断是否接受／转交”这一并行研究路线；把它限定为只有数学或中间计算才考虑，过于狭窄。它也没有证明SII、Kev或其他一步判断模型的后训练路线应被整体替换。** 本节属于来源与源码审查，没有重训或重算该论文逐题结果。

### 8.1 它实际训练什么

模型先自回归生成一条简短推理`r`，在`Answer:`之后读出候选token的分布`uθ(x,r)`；部署一次请求暴露的是一条推理后的分布。PRDO对每个训练问题采样四条推理，分别对各自分布计算Brier或log proper score，再加到初始冻结模型的逐token KL。**这是有推理生成的条件概率读出，不是零生成、一次前向完成整个任务的决策头。** 训练需要答案标签，但不需要正确推理文本或人工标注置信度。[§2–4.5](https://arxiv.org/html/2609.38850v2#S3)

主方法只沿读出及token锚定求路径梯度，采样的推理没有score-function奖励。若把总体目标写成`E[r~πθ] S(uθ(x,r),y)`，完整梯度还含`E[S∇logπθ(r|x)]`；主方法没有这一项，可理解为对采样路径使用半梯度，不能称为完整期望目标的无偏策略梯度。论文可选第二阶段在系数`c=1`时补足相应score-function项，实际用`c=.3`下调；它不是主结果的必需步骤。**没有推理奖励不等于冻结推理权重**：生成与读出共享的参数都在更新，KL约束因此仍有作用。[§4.5–4.6](https://arxiv.org/html/2609.38850v2#S4.SS5)、[训练源码](https://github.com/ZimmyGao/openjev-rlcd/blob/5859d2b893314fb3581f06e4e36c303e372b3f48/openjev_rlcd/train.py#L932)

论文比较了不proper的线性dense score、Brier／log、自己的／冻结模型的推理、逐推理／混合分布等因素。它支持“实际部署消费哪个概率对象，训练就要对准哪个对象”，没有把改进简单归因于用了RL、dense梯度或更好的推理文本。主方法和在线／冻结模型推理之间未检出稳定差异，也不能据此证明两者等价。

### 8.2 最强正面证据与相反结果都要保留

同底座、同问题和结果流、相同400更新步、每题四条推理，所有方法在开发集做温度缩放。四个底座在1,000题MMLU-Pro上的主比较如下；差值为PRDO-Brier减GRPO＋TS，括号为**未做多重比较调整的95%案件bootstrap区间**，负值有利：[补充表1，主比较C](https://arxiv.org/html/2609.38850v2#A7.T1)。

| 底座 | Brier差值 | AURC差值 |
|---|---:|---:|
| Qwen3-0.6B | −.071 [−.085,−.057] | −.161 [−.193,−.130] |
| Qwen3-1.7B | −.080 [−.095,−.065] | −.154 [−.183,−.126] |
| SmolLM3-3B | −.076 [−.092,−.060] | −.133 [−.162,−.104] |
| Phi-4-mini | −.068 [−.084,−.052] | −.106 [−.131,−.082] |

八项主比较都通过Holm校正且三个种子的差值方向一致，种子＋案件层级区间也排除0。这是比单模型单种子更强的支持；最明显的支持来自知识类选择题，不能据“需要推理”就把适用范围缩成算术。准确率提高2.6–4.1pp是次要指标，其中Qwen3-1.7B的种子＋案件区间跨0，证据弱于主要概率／排序指标。

**数学验证反而暴露取舍。** 在Qwen3-0.6B GSM8K-Verify上，AURC下降.093，但准确率下降2.7pp（案件区间−4.3至−1.1pp，Holm `P=.0048`，层级区间跨0）；Qwen3-1.7B没有检出差异。追加至五seed后，0.6B GSM8K仍少答对2.0pp、AURC仍更好；SVAMP迁移准确率低4.0pp（−6.2至−1.8pp；五seed同向，层级区间也排除0），排序仍改善。这明确区分了“挑出可接受答案”和“解决更多题”。[§5.1、附录E/X4](https://arxiv.org/html/2609.38850v2#A5)

第二阶段不能只用“没有增益”概括所有情况：预先规定的两阶段对一阶段比较没有稳定显著增益；后续预算匹配探索中，0.6B GSM8K的GRPO continuation比相同额外步数的PRDO continuation准确率高4.4pp（2.7至6.0pp），三个seed同向且层级区间不含0，但在MMLU-Pro上Brier和AURC更差。**proper的推理奖励未被证明优于普通正确性奖励，优化读出和优化推理可能需要不同取舍。** [附录E/X2](https://arxiv.org/html/2609.38850v2#A5)

KL也不是普遍的必需定律。去锚定探索使0.6B GSM8K准确率提高3.8pp，却损害0.6B MMLU-Pro的概率质量与排序；推理格式亦明显漂移。先复现完整配方，再按任务诊断锚定强度，不沿用“没有KL约100步必崩”的v1局部现象当默认规律。[附录E/X3](https://arxiv.org/html/2609.38850v2#A5)

### 8.3 部署门槛、统计与数据曝光

论文的oracle coverage用测试标签选择可接受前缀，不能作为部署阈值效果。它还提供独立校准集上的19点固定阈值网格、Clopper–Pearson上界及Bonferroni控制：在相同总体假设下，以至少0.9概率控制被接受答案的错误率。20%错误预算下，PRDO在四底座中三个的所有seed找到阈值，GRPO十二次MMLU运行都没有。Qwen3-1.7B的实际测试覆盖为10.3–16.1%，而其10%错误预算下没有阈值通过；这比测试oracle数字保守得多，不能移作企业客服风险承诺。[§4.9、补充表4](https://arxiv.org/html/2609.38850v2#A7.T4)

主研究有三seed、配对案件检验、Holm家族和层级bootstrap；也披露了证据弱点：分析计划未外部注册，四个最终测试／校准样本被早期smoke读过；旧版测试转为开发验证；ChaosNLI没有未用数据，属于已读测试上的机制复核；RLCR是事后比较，CREDO未调优且排除一次崩塌。MMLU-Pro从官方test内重新划分训练／开发／最终测试；GSM最终测试来自未用于本实验训练的官方train题，不能宣称排除了基础模型预训练曝光。较长thinking实验存在不等截断率，不能据其数值认定无预算限制时仍同样胜出。[附录A–D](https://arxiv.org/html/2609.38850v2#A1)

关于计划制定时序与结果归档的上述说明仍是作者报告；分析计划原件与完整版本历史尚未在本次可读仓库中取得，未独立认证“所有分析均在看结果前冻结”或不存在选择性报告。披露较完整提升可审查性，不等于已完成外部审计。

训练步数与采样条数匹配不等于GPU时长、生成token或推理预算完全相同，尤其直接SFT不生成推理。论文支持四个小模型、闭集、短推理上的概率和排序结论，未验证中文企业客服、动态工具目录、真实拒判代价或多轮生产结果。

### 8.4 它不直接否定SII平均教师目标

PRDO批评的是：**训练中的模型只被奖励其多条读出的平均值，却在部署时只取其中一条**；平均值可掩盖不可靠的单条读出，其Brier分解含分歧项。SII是把固定教师两条推理的均值当作标签，训练一个无推理student在一次前向中输出该分布；student训练时没有同时移动教师各条读出去赚取分歧收益。两者的被优化对象和部署单位不同。因此该论文不构成对SII自蒸馏的直接反证；SII仍须审计教师偏差、均值目标和独立业务金标，不能把蒸馏一致率当真实校准。[PRDO §2、§6](https://arxiv.org/html/2609.38850v2#S2)、[SII §6.2](https://arxiv.org/html/2610.03935v2#S6.SS2)

### 8.5 对底座与方法候选的实际调整

| 目标 | 本文对既有候选的影响 |
|---|---|
| 要求零生成、低延迟的客服判定／工具路由 | 保留SII类自蒸馏、Kev类自有标签SFT、简单分类／检索等对照；PRDO没有与这些成品同数据后训练比较，不能凭本文排序或淘汰它们 |
| 系统本来就要生成推理，再根据概率接受或转交 | PRDO应成为并行主研究路线，而不只是“只有数学题才用”的远期选项；与同底座SFT、GRPO、proper-score读出及独立校准做预算明确的对照 |
| 多模态候选如Intern-Decision | 本文是文本闭集实验，不能据此决定多模态适配优劣或Mac训练路径 |
| Nimble式关键事实对照数据 | 仍作为独立的数据质量因素保留；本文没有隔离证明此类增强更好或无效 |

选择PRDO时，第一项验收应是**目标风险约束下可接受覆盖与成本是否改善，同时总体任务正确率不超出预定退化预算**，不是先指定必须提高准确率，也不是用AURC进步掩盖实际少解决了任务。客户事实、政策、前置资格及执行权限仍需独立业务合同。
