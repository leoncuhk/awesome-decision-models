# 企业独有数据的决策模型后训练：选型与实施指南

更新：2026-11-20。目标：**用企业独有数据改善明确的决策问题，在质量、风险、算力与完整成本约束下选出可实施方案，验证相对当前生产方案的增益。** 本页是企业后训练的唯一主线正文；通用事实沿用[模型卡](models.md)、[证据台账](evidence.md)与[来源登记](sources.md)。

当前处于研究与协议准备阶段：没有本次目标企业的数据、训练结果或生产对照；目标训练机为用户的M5 Pro 48GB，未访问或运行该设备。下文分别标明来源报告、公开产物核查与实施建议。

**当前实施起点：** 用可信领域标签比较简单监督基线、候选原版和小模型直接适配；CE／BCE是起点，硬标签与有依据的软目标按任务选择，概率校准和完整接受／转交策略另验。先验证可用的小模型，再决定是否增加教师、蒸馏、级联、部分反馈或推理训练。当前没有得到企业效果最优的模型或固定升级链。

阅读顺序：[业务合同](#decision-contract) → [方法与基座](#method-selection) → [选型证据](#evidence) → [企业数据](#data-plan) → [训练实施](#training-protocol) → [业务验收](#enterprise-gates)。

<a id="goal"></a>
## 1. 从生产问题定义训练目标

先选一个重复发生、可核对的错误或成本瓶颈，例如漏判必要路径、撤销目标后误触发旧流程、需要补证时贸然执行，或大量简单判断占用昂贵调用。记录当前系统、可见证据、错误代价与任务终态；模型更新只改变其中一个明确环节。

“预期业务收益、证据扎实程度、成本和风险”是合理选择标准，但应落实为：与当前方案相比，完整任务正确完成或关键错误改善多少；相应对照是否匹配目标任务和训练预算；标注、教师、训练、推理、回退及返工的总成本如何变化。尚无目标域测量时，这些是待检验的先验判断，不能填成确定排名。

客服常见特点须在实际任务中核实，不能直接当作四条公理：

| 工作假设 | 必须核实的条件 |
|---|---|
| 很多轮次是读已有证据的分类 | 固定动作集合不意味着证据齐全、判断简单或无需推理；历史／档案／知识必须确实可见且足够新 |
| 标签有噪声，也可能多解 | 区分错误标注、缺事实、真正分歧和多个合法动作；不同情况不应统一平滑成一个分布 |
| 只观察选中动作的结果 | 还要核结果语义、观察窗口、缺失、人工干预及选择策略；“没再联系”不自动等于动作正确 |
| 需要低延迟和概率门控 | 只有实际使用概率做策略选择时，才需验该策略下的风险／覆盖；局部低ECE不保证完整动作安全或任务成功 |

<a id="decision-contract"></a>
### 决策合同：模型判断与业务执行分开

输入是决策前可见的当前目标、必要历史、已确认字段及来源／时间、未知字段、当前流程、已完成动作与候选路径版本。根据具体瓶颈选需要的输出，不要求每个项目都训练以下全部四项：

| 输出 | 标签／证据 | 系统确定性职责 |
|---|---|---|
| 路径适用性 | 相关性与是否满足条件分开；允许多路径、可替代动作及证据不足 | 身份、资格、允许操作和状态新鲜度 |
| 信息充分性 | 缺少哪项事实、应查系统还是澄清 | 字段与来源约束、取数及回执 |
| 冲突 | 客户目标、事实、政策或动作的具体矛盾 | 政策版本、来源权威、显式互斥及退出规则 |
| 优先关系 | 前置依赖、并行、撤销和暂缓 | 冻结的依赖／优先约束及客户明确顺序 |

条件标签可设计为`supported / refuted / unknown / conflicting_evidence`，由代码组合到路径集合；这是自定义合同，不是任何供应商原生保证。`unknown`是业务状态，不等于概率接近0.5；模型可以高置信地判定缺证据。相关性、资格、动作完成、客户获益和因果增量是不同终点。

**合成例：subscription-demo-v1。** 客户说“别再扣费，上次那笔也退掉”；身份、订单与退款状态尚未核实。可同时存在取消续费与退款诉求，当前允许下一步包括身份／订单查询，不能直接执行两个写操作。该虚构合同规定：退款须有显式请求、核实身份和订单且未退过；查询政策不授权写入。客户随后改为“上次已退，我只要发票”时，应重新确认目标及系统状态，终止不再适用的退款路径。八个[合成案例](examples/skill-loading/cases.jsonl)仅解释合同，不是企业训练或效果证据。

最新政策、金额、日期、权限和精确计算应由版本化证据与代码提供。训练应学习稳定的语义／条件边界；不能用更新权重补偿owner丢失、过期状态、坏工具或相互冲突的制度。

<a id="method-selection"></a>
## 2. 方法与基座：把Top 5改成条件选择

原Top 5把参数适配、标签生产、模型压缩、日志学习和运行时计算放在同一序列，且没有匹配企业实验支持固定名次。保留五类潜力，按入口和增量证据选择：

<a id="current-decision"></a>
<a id="learning-signals"></a>
| 方法／作用 | 当前选择 | 准入、对照与不成立的推论 |
|---|---|---|
| **领域监督适配＋独立校准** | 可靠标签任务的优先实验起点 | CE适合互斥类，BCE或其他明确目标处理非互斥命题／多标签；可信硬标签可直接用。LoRA、只训头和全参按底座、标签预算与资源比较；没有软标签必胜或成本普遍最低的结论 |
| **教师／推理到读出蒸馏** | 标签预算有限且教师确有质量增量时加入 | 先用独立gold确认教师／thinking优于便宜读出，再比较教师hard、soft或真实分歧分布。它不能自动修正噪声、歧义和政策错误；教师一致率不是业务真值 |
| **小模型蒸馏／级联** | 质量已可达而服务成本仍有瓶颈时比较 | 直接适配小模型是必要对照。蒸馏把能力压入学生，级联在运行时保留强模型，机制不同；两者均不要求先训练27B |
| **CAPS等部分反馈学习** | 反馈、支持与模型语义匹配后再评估 | CAPS主实验是单gold类别对错的模拟日志；不能原样把退款满意率放进单一softmax。比较positive-only、利用负例的学习和可获得的完整标签基线；不默认每周自动更新 |
| **保留推理的选择性判断／PRDO** | 已证明推理在目标失败上有净收益时研究 | 与同底座生成式基线匹配预算。PRDO更新权重，不是普通事后校准；不只限政策／算术，也没有固定少数流量比例。与按需推理系统结合仍需新实现和实证 |

**数据覆盖由承诺能力决定。** 要服务长历史，就训练并评估真实长历史；要保留NONE、二元验证、评分、视觉或生成能力，就准备对应回归切片。只做固定choice的系统不必补造全部题型；“混题型”“长度完全一致”也不是所有任务的统一配方。可比较合适的replay／anchor，但不能从一个模型继承固定KL系数。

**不按算法名称永久排除。** GRPO／RLVR的特定正确性奖励可能破坏概率质量，但不证明所有奖励、估计器和底座都如此；RLCR、Brier或其他校准目标亦有各自部署对象。无独立收益证据时保持简单基线，有匹配问题时再做消融。使用Jev输出训练竞争模型存在明确条款风险，未取得适用授权时不把它设为默认教师；本指南未裁定任何第三方主体是否违约。[TypeSafe条款](https://typesafe.ai/legal/mca)

<a id="readout"></a>
### 读出、推理和参数化是不同维度

| 选择 | 需要核查什么 |
|---|---|
| 固定分类头／候选token／pointer head／encoder评分 | 训练与服务的候选、分词、归一化、排序和截断是否一致；未知候选是否受支持 |
| 直接读出／先推理再读出／按需级联 | 实际返回哪个分布；额外prefill、生成、再读出、超时和回退均计成本 |
| LoRA／head-only／全参 | 哪些参数真的更新、是否保存自定义head、adapter是否已合并；推理可加载不证明反向可运行 |
| 温度或其他外部校准／权重训练 | 前者不更新主干；正温度保持同题argmax，但可改变ordinal期望和后续策略。字段、route与联合选择的校准对象不能混同 |

逐命题BCE须匹配Bernoulli／多标签读出；单个choice softmax不能同时表示多个动作都可能很高的成功率，其和受1约束，而各动作成功率之和可以大于1。

模型输出类型合法不等于事实正确；一次HTTP也不保证一个回合只进行一次模型工作。多个问题共用state、互不读取对方答案，不等于统计独立。若第二题候选依赖第一题结果，应显式实现序贯或联合合同，不能靠同请求叙述获得条件化。

<a id="model-candidates"></a>
### 第一轮具体比较哪些模型

先保留当前系统及合适的监督分类／检索基线。可训练候选限定为少数；下表是研究角色，尚无目标企业适配后的赢家。

| 角色 | 候选与可查入口 | 关键实施边界 |
|---|---|---|
| 直接自有标签适配 | **Kev-4B**的`--data`、`--init_from`与pointer head；同原版作前后对照 | 固定问题／标签合同；MPS分支存在，Qwen3.5混合结构backward、内存和保存重载仍须目标机实测。[训练源码](https://github.com/jaredpalmer/kev/blob/051142bf849c2c6ad3f23e17a7b5aea2686d9a91/kev/train.py) |
| 读出／参数化对照 | **Qwen3.5-4B指令版＋明确的候选读出／LoRA实现** | 作为原始底座路线对照；不能只改模型名就复用另一家的head。当前无本仓Mac配方实测。[Inner Jev配方](https://arxiv.org/html/2610.17205v1#S4) |
| 能力与蒸馏参照 | **SII-Decision-4B**；27B只在可承担的教师／质量参照条件下使用 | 4B基于Qwen3.5、27B基于Qwen3.8；原法从原始底座蒸馏，发布loader要求`gold_target/train_target/p0`。gold字段不必被解释成人工来源，但其语义及hard-Noul／验证用途要明确；不是仅换企业硬标签即可复用的续训入口。[固定代码](https://github.com/amazingljy1206/SII-Decision/tree/1723d83cbda69f48641c273280b5a2d06d6b3510) |
| 多字段／视觉专项 | **Intern-Decision**等与任务匹配的产物 | 官方XTuner／CUDA训练语言骨干、冻结视觉部分；不是现成Mac LoRA。字段共用序列也不保证顺序或关系不变。[官方训练入口](https://github.com/InternLM/Intern-Decision/tree/a7b01e276cd5e18bae640be925e685ba6f5159ad) |
| 托管定制备选 | 百炼`decision-model-preview-2026-09-24`的`efficient_sft` | 官方有LoRA流程，但需开通、数据可获准上云且匹配版本／地域／schema；部署费用与训练总成本分开。不是微调TypeSafe Jev，也不是已持有开放权重。[官方指南](https://help.aliyun.com/en/model-studio/decision-model-tuning-guide) |
| 强参考及其他机制 | PPLX、Clef、StartLux、许可允许的强LLM；Nimble的数据构造可跨路线使用 | 权重／代码／原数据／完整训练器分开。PPLX已到v1.3；StartLux权重非商业许可且完整v1.1训练包未定位；Jev不提供客户FT。详见[逐项模型卡](models.md) |

不因可在Mac训练而给Laya质量优先级。经典322M／421M encoder可作有理由的成本基线；当前Laya／Vega的4B reader拟合头是另一个对象，不能互借Banking77成绩。小于2B也不应按尺寸排除，是否纳入由目标错误和预算决定。

<a id="evidence"></a>
## 3. 哪些证据支持上述选择

以下均为作者报告或公开产物核查，未在本仓进行新模型推理／训练。数值的任务、候选与分母一并保留；相同作者的论文、代码和转述只算一个证据家族。

| 关键证据 | 实际支持 | 对本次选型的约束 |
|---|---|---|
| [Inner Jev表5／附录F](https://arxiv.org/html/2610.17205v1) | Gemma31B将soft转hard未检出Capability差异；冻结主干的head损失实验中，温度后ECE差异有限 | 支持简单监督基线，不证明soft必优、换loss普遍无效或所有架构head-only无效。70.3／14.1点是Gemma的Capability，非Qwen accuracy |
| [同文4B教师消融与最终配方](https://arxiv.org/html/2610.17205v1#A2) | 76.8→85.0为外部七组macro accuracy，包含LR、已训练31B教师目标和格式等改动 | 不是27B→4B单因素增益；400步是固定WSD日程终点，不是通用早停线；T≥1只是该实现的保守措施 |
| [JEVal／SII v2](https://arxiv.org/html/2610.03935v2) | 同表SII4B／27B accuracy71.92／79.24%，Kev4B／27B68.90／77.17%，Intern4B70.74% | 分母10938个choice/noul，invalid计错；ECE／Brier仅有效输出。SII也由基准作者提出，分数不是纯中文客服、同预算适配或生产胜负 |
| [CLINC路由比较](https://arxiv.org/html/2610.00346v2) | 600个ID上监督DeBERTa .953、Jev零样本 .913；所测Jev hard-domain两步联合.673 | 训练暴露不同。小监督模型要保留；150不是flat／分层通用分界，不能把gold域内细分分数与两步交集混用 |
| [LLM-as-Jev v3](https://arxiv.org/html/2610.02076v3) | 意图适配可提高域内成绩，但窄覆盖会使特定跨题型表现退化；81.4→74.9是231题JevBench列 | 支持保留承诺能力的回归集；不代表全部通用能力下降，也没有证明混所有题型必然最优。论文配方可读不等于原作者训练包已可执行 |
| [CAPS v1](https://arxiv.org/html/2611.15572v1) | 0.6B／5000日志的Banking任务，CAPS .931／ECE.025对positive-only .905／.078 | **10-way**（gold＋8干扰项＋other，other不为gold），非77-way；三seed对一个基线seed。模拟反馈不能当自然企业日志，四种方法的完整标签负结果也仅限所测schema／指标 |
| [PRDO v2](https://arxiv.org/html/2609.38850v2) | 四个小底座MMLU-Pro相对GRPO＋TS的Brier和AURC改善；0.6B数学验证accuracy反降 | 主阶段是逐推理proper-score路径梯度＋token KL，共享权重更新；可选第二阶段不普遍增益。5%处的高覆盖是oracle，正式阈值另报10／20%，不能当5%企业SLA |
| [StartLux v2](https://arxiv.org/html/2610.17309v2) | 按需推理与策略感知校准值得研究；RLCD²效率收益明显，质量有任务／预算取舍 | 论文gate=.9时DI上的28–33%不是客服流量比例，同27B在DecisionPivot触发61%。9B pair53.3→59.9有正增量，不能写全部accuracy变化均在噪声内；它不是PRDO的同义实现 |

**标签歧义证据须核分母。** [工具选择审查](https://arxiv.org/html/2610.02267v1)的19.8%是全部400道hard工具题中79题被LLM判有其他有效工具，不是19.8%的模型错题，也非独立人工真值。它支持审查允许集合，不能证明教师soft比人工hard更诚实。该来源K50摘要还混用了完整80题与unique57题，比较应回到相同子群。

**避免把榜单当后训练选择。** StartLux的10月DI榜首是历史事实；11月19日[DI0.4.1固定汇总](https://huggingface.co/spaces/multimodalart/jev-decision-index/blob/4ee57a1610e0547634ba0ec11990d10122672191/data/v03.json)已非第一，且任务／权重／刻度改变。PPLX v1.2的68.09／58.88是public joint请求分数；它们都不能推出目标企业的适配赢家、数据效率或Mac可训性。

| [Parlant固定源码](https://github.com/emcie-co/parlant/tree/07b2bcb4bebfeda7c53f1e2bbf2c68415f389e83) | 共用state、逐条件判断、代码关系解析及工具后重判可借鉴 | 高召回相关性过滤不等于执行资格，ledger不等于成功回执。回退、概率有限性／归一化／成员校验要有显式合同；已有[隔离协议观察](examples/service-routing-review/parlant-protocol-observations.json)非完整引擎或模型运行 |
| [Modem事件触发](https://modem.ai/blog/smart-triggers)／[Entagl回放](https://www.entagl.com/blog/typesafe-jev-benchmark-ai-decision-models) | 事件内可判条件可前置过滤；owner及流程状态缺失会导致错路由 | 依赖外部历史时仍须取证／启动Agent；历史回放输入不匹配不能单归因模型，阈值回退不保证更好 |
| [Audiala回滚](https://audiala.com/blog/jev-in-production) | 组件更快仍可能使完整任务更慢、更不可靠，应保留回归与回滚 | 使用方报告23分钟后回滚；稳定通过38→33，路由中位382→294ms但完整轮次8677→9262ms。不是随机生产对照，却是必须保留的负例 |

[REFLEX v1](https://arxiv.org/html/2609.26532v1)支持有界控制拆分，但没有证明专门决策器胜过所有便宜级联。为识别权重训练的净增量，应保留同现用模型的提示精简／推理预算调整、现成便宜LLM→强LLM级联等无训练对照；只胜过最昂贵的原方案不足以选出最合适的方法。

本轮公开资料没有建立“某开放方案用独立企业数据后训练，并在本次目标中文业务生产对照中胜出”的答案。生产使用、源码可查、公开预测复算和真实业务增量分别成立，不能串接为已证成功链。

<a id="data-plan"></a>
## 4. 企业数据：先确定可学信号

一个标注单元是**案件在决策前的状态**，不是未来结局或任意一句聊天。保留如下字段及责任；具体JSONL要按所选trainer转换，不先设计跨项目共享平台。

| 数据组 | 最少内容 |
|---|---|
| 追溯 | 案件／会话／客户组ID、决策时间、来源与权利范围、政策／候选schema版本 |
| 当时输入 | 当前目标、必要历史、事实值及来源时间、unknown、owner、已执行动作及工具回执 |
| 决策合同 | 输出字段、候选、前提／依赖、允许集合、禁止动作及证据ID |
| 监督目标 | 人工／教师／规则来源、裁定和分歧；hard、soft、多标签或允许集合的语义 |
| 结果反馈 | 选中动作、日志策略及可用propensity、结果事件／窗口、后续干预、缺失／迟到和纠正 |
| 任务终态 | 正确完成及副作用断言、返工／再次联系等定义、实际费用和延迟范围 |

历史行为不自动是gold；优秀坐席也可能有多个合法动作。未来订单结果可以帮助裁定，但不能泄漏为当前输入。未知反馈不能填0，未加载工具不能造为负例；仅采集人工升级或已接受案件都会漏掉相应高置信错误或被抑制的有效请求。

**四类标签处理：**

- 明确、可信的单类标签可直接hard CE；不为显得先进强制软化。
- 独立命题／多意图用符合部署语义的多标签、允许集合或逐条件目标，不将多个都正确的动作硬凑为唯一类；集合监督也须说明怎样算整条决策正确。
- 可复核的真实分歧可保留分布；教师logit、口述confidence、重复采样频率和真实业务概率不是同一信号。教师需要独立审查一致样本和分歧样本。
- 缺信息、OOS、缺候选、政策冲突与目标撤销单列；均匀target可作实验正则，不等于已学会可靠拒判。

**切分先于增强。** 按客户、案件、会话、来源与时间分组；同案件的候选配对、翻译、改写与反事实样本同组。职责分别为Train更新权重、Dev选择方法／预算、Cal-fit拟合概率、Cal-policy选择完整接受／转交规则、Test冻结确认。可论证的交叉拟合是另一协议；共享校准样本的探索性扫描不能继承独立校准风险界。自然流量或已知抽样权重估计总体风险／费用，困难例与少数高损失错误单列。

数据构造优先覆盖相邻能力硬负例、最小事实改动、否定／例外、缺必要事实、多合法项、目标改变、新政策、长历史和无工具需求。Nimble式事实改动是数据因素，不是另一种底座或contrastive loss；控制数据量、标签频率和模板后才判断它有无增益。

公共材料只用于对应诊断：[ABCD固定资料](https://github.com/asappresearch/abcd/tree/6b8700ce67c6b37b062dd7a60abc76d7ef832a97)可借流程／动作设计，但全会话subflow不等于每个可见前缀都可唯一识别；CLINC可测OOS／意图混淆，SGD-X可借描述变化，不能替代企业留出。[τ²固定评估合同](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/docs/evaluation.md)用于最终状态思想，版本、数据许可和模拟／真人边界分别保留。

<a id="training-protocol"></a>
## 5. 实施：逐步证明增量

| 步骤 | 具体交付与对照 | 推进／停止依据 |
|---|---|---|
| 1 定义与诊断 | 一项真实失败、冻结合同、当前系统及必要的无训练优化／便宜级联对照、可授权样本及独立标注小面板 | 先确认错误来自可学习判断；状态／工具／政策问题先修对应环节 |
| 2 候选准入 | 精确权重、代码、tokenizer、head、schema与许可证；转换少量人工核过的样本 | 实际forward／backward、有限更新、保存重载与服务概率正常，才扩大数据 |
| 3 直接适配 | 固定候选与输入，对比原版、简单监督基线、目标小模型直接训练；记录标签量学习曲线及选择预算 | 关键错误和完整成本存在有用增量；失效先诊断，不靠扩大轮数保护既有推荐 |
| 4 必要的消融 | 同数据hard／soft、LoRA／head或其他必要参数化；有明确问题才加teacher、replay／anchor | 一次改变一个因素，或声明因子设计；步数相同不自动代表tokens／算力相同 |
| 5 部署优化 | 需要时比较直接小模型、蒸馏学生、实际级联；记录量化前后概率及判断差异 | 同质量／预定非劣界内完整成本改善；强模型在defer子集上应有实测增量 |
| 6 冻结确认 | 锁定model/schema/runtime、校准、完整门控／回退和预算，运行一次独立Test | 报配对区间、失败与退化；未显著不等于等价，未达标则缩窄、诊断或停止 |

不默认“教师soft→训练27B→4B→每周CAPS→PRDO”。教师已够好可直接产标签；小模型直接达标则不必付教师训练费。若转交率为q，级联还要支付首阶段、转交子集的强模型、重试及人工等成本；强模型总体accuracy高，不保证在被转交的样本上更好。[级联对照](https://arxiv.org/html/2610.00346v2#S5.SS3)

<a id="mac-feasibility"></a>
### M5 Pro 48GB：训练准入，不作内存／耗时承诺

- 固定模型与代码revision、Python／框架／算子、精度及完整输入分布。先跑含代表性最长状态／候选的真实前向和反向，再测少量更新；记录峰值、swap、跳过样本、梯度有限性和失败。
- 检查head或特殊marker是否实际被训练、候选顺序是否映射正确。保存adapter／head／tokenizer／schema和校准，重载后对同批输入比较概率与最终判定；服务端不能悄悄改模板或截断。
- Kev有MPS分支但目标机backward未验证；SII公开wrapper用多GPU，已核LoRA发布为合并BF16独立权重、训练器另存adapter；Intern当前CUDA全语言训练不能按推理内存估算。改成MLX／LoRA是新实现，须重新验合同。
- 27B BF16仅权重通常已超48GB；量化教师推理与27B训练是不同任务。PRDO论文每run用48GB Ada，**另有125GB主机内存**；CPU offload不能给48GB统一内存凭空增加容量。[PRDO实现](https://github.com/ZimmyGao/openjev-rlcd/tree/5859d2b893314fb3581f06e4e36c303e372b3f48)
- 首轮数据量、更新预算、学习率、LoRA范围／rank、batch与停止规则先在Dev和资源预算内冻结；不抄400步、某个学习率或某张H100的美元数作保证。没有目标机receipt就写未测。

实际权重训练沿用工作区既有`improve/post-training`入口；企业数据、业务runtime及发布责任归实际业务项目。当前仓库维护知识与公开证据，不收原始客户会话、私有训练输出或企业凭据，也不新建空实验工程。

## 6. 验收：完整策略和真实任务

| 层次 | 必报指标／对照 |
|---|---|
| 决策质量 | 意图／条件／路径指标、允许集合与关键误触发／漏判；无效输出、超时和回退不剔除 |
| 概率与选择 | 明确口径的NLL、Brier、ECE及风险—覆盖；分母、分箱、失败处理和阈值选择组写清 |
| 鲁棒与退化 | 顺序、同义条件、相似工具、缺候选、unknown、OOS、过期事实、撤销／多诉求、长输入及来源／语言／政策漂移 |
| 完整交互 | 正确完成、禁止副作用、无效澄清／重复联系、人工复核与返工；更换动作后的结果需完整交互验收，静态日志不提供反事实终态 |
| 完整成本 | 标注、教师、训练／调参、检索取数、冷暖推理、重试工具、人工及修正；在真实长度／并发／cache下记录p50／p95 |
| 不确定性 | 同案件配对、按客户／会话等独立组估计区间，种子不替代新增案件；预定非劣界／有用增量和多重选择规则 |

**“只允许5%错误”和ECE不是两项足够的终验。** 5%只是可选业务预算，关键错误可能需要另设约束；测试标签上挑出的最大可接受前缀是oracle，不是上线阈值。正式风险控制有固定评分器、独立数据、抽样／交换性等具体假设；漂移后需重新确认，理论proper目标或NONE选项都不单独提供保证。

温度要对实际返回的对象拟合：argmax直接读出、推理后读出、融合结果和级联返回可能有不同校准。按题型温度可以比较，但不能替代route／字段／完整选择策略的验证。[StartLux v2的策略校准](https://arxiv.org/html/2610.17309v2#S5.SS5)和[校准基础](https://proceedings.mlr.press/v70/guo17a.html)说明两者边界。

两个问题的选项互不依赖，也不自动给出联合正确率。即使在同一接受子集上两问真实边际均.95，独立时联合正确仅.9025；实际也不能假设独立。用案件级Cal-policy验证整个“意图＋动作＋约束”的规则，不能把两个自报置信度相乘就当风险证书。

<a id="routing"></a>
**路由结构与技能加载只在它们是瓶颈时比较。** 选项数、描述预算和可靠外部域信息决定是否试flat、检索、多候选或分层；Jev的层级.673是404／600联合正确，gold域细分另为567／600。显式NONE与外部gate等是候选机制，须同时测OOS误接受、域内覆盖与漏判。按需加载另固定判断器／执行器，分别测候选召回、实际加载、遵循、执行和任务终态；依赖闭包或状态新鲜度不能由top-k命中代替。

<a id="production"></a>
**生产推进：** 冻结配置后先影子观察，盲审分歧也抽查一致／高置信自动接受及被抑制案件；再做有界对照、停止／回滚和结果成熟窗口。概率门槛不授予权限，执行回执与真实结果分别记录。离线分数提高而任务成功下降时，检查状态、工具、候选、策略和评测等原因，不能只调严阈值或拆细动作。

学习闭环由反馈质量和漂移触发，不按周自动重训。只有日志定义和支持满足条件，才研究CAPS等部分反馈；多动作均可能成功、延迟与干预显著时，需要不同结果模型／识别合同。没有解决真实失败、未胜过便宜基线或完整成本无收益时，保留负结果，停止扩大投入。
