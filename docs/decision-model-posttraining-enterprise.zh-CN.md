# 企业决策模型后训练：从真实问题到可接受的新版本

核查日期：2026-11-19。本文研究如何用获授权的企业数据改进有限答案判断，不代表已经取得客户数据、运行训练或证明业务增益。当前讨论的目标硬件是单台M5 Pro、48GB；本文没有访问该设备。模型卡、代码、训练数据和服务接口分别核查，公开benchmark与生产效果分别解释。

**合理起点是一个已观察到的企业判断错误或成本瓶颈，以及同条件可复验的基线；模型家族与训练目标由这个问题决定。** 没有企业数据时，可以完成训练链路研究和公开数据诊断，不能把合成题改善写成企业问题已解决，也不应预先宣布Laya、Qwen或RLCD胜出。

入口：[当前四项判断合同](domain-path-applicability-research.zh-CN.md) · [业务实验入口](dynamic-skill-loading-business-playbook.zh-CN.md) · [训练目标与论文核查](decision-model-posttraining-method-audit.zh-CN.md) · [平台与实际可训练性核查](decision-model-posttraining-platform-audit.zh-CN.md) · [Mac可执行起步配方](decision-model-posttraining-mac-recipe.zh-CN.md)。多模态证据获取与文本化Skill路由保留各自问题，不自动成为彼此的前置模块。

## 1. 企业到底要改哪个判断

面对当前诉求、相关历史、已确认状态与候选路径条件，保持四项独立输出：

| 输出 | 标签及依据 | 保留给确定性系统的职责 |
|---|---|---|
| 路径适用性 | 哪条路径相关、适用／不适用／证据不足；允许多条同时成立，附当时证据 | 身份、资格、状态新鲜度与操作权限校验 |
| 信息充分性 | 缺少哪项必要事实，应查系统还是向客户澄清 | 必填字段、数据来源、有效时间与取数动作 |
| 冲突 | 当前目标、客户陈述、政策或状态是否矛盾；矛盾位置是什么 | 显式互斥关系、政策版本和失败退出规则 |
| 优先关系 | 哪些路径有前置依赖、可并行、被撤销或应暂缓 | 冻结的依赖图、客户明确顺序与业务优先约束 |

模型最适合承担有证据的语义条件判定。路径相关、符合执行条件、动作完成和客户获益是不同终点。置信度高不代表优先级高；历史转化率高也不自动表示某个动作有因果增益。若错误来自丢失当前owner、状态过期、政策冲突或工具执行失败，应先修输入和系统合同，再考虑更新权重。

首轮应收紧到四项中的一个已知失败：例如必要路径被漏判、目标撤销后仍触发旧流程，或大量简单判断占用了昂贵模型调用。先固定现有生产基线及关键错误定义，避免同时建设全新Agent、技能加载器和模型训练系统。

## 2. 目前公开企业证据到哪一步

下表的“生产”指来源明确报告的集成身份，不等于公开随机对照或本仓复现。

| 一手来源 | 训练与数据证据 | 可支持的结论 | 不能支持的结论 |
|---|---|---|---|

| [Entagl历史客服回放](https://www.entagl.com/blog/typesafe-jev-benchmark-ai-decision-models) | 真实历史消息回放与规则复核；未训练Jev，双方状态信息不完全相同 | 当前owner、已收集事实等状态缺失可造成真实错路由；阈值回退不保证更好 | 不能把历史回放或构造题成绩当生产A/B，也不能把状态差异归因于模型能力 |
| [LayaStudio](https://github.com/biplovgautam/LayaStudio)、[Laya官方训练](https://github.com/NandhaKishorM/laya/blob/d1282e791d71e92f24f816ff3836e4fd1c2ded4a/docs/finetune.md)及[公开Skill路由实现](https://github.com/ericmjl/pi-laya-skill-router) | 有可审查的本地适配代码、公开集／个人会话标签或教师标签；记录本身不能视为企业独立标签 | 本地小模型适配、保存与重新评估具有实现起点 | 个人会话／合成示例不是企业生产收益；加载记录与教师判断也不是完整任务真值 |

本轮可核来源没有建立“一个公开可完整复现的开放决策模型，在独立真实企业数据上完成后训练，再通过生产对照证明收益”的通用答案。各案例提供的是部分证据，不能串接成一个已验证方案。现成源码与本地可训练性强，决定工程起点；企业独立标签和匹配对照，决定能否声称有效。

## 3. 模型家族：比较可训练契约，不拼混合榜单

“直接返回概率”可以来自固定分类头、动态候选评分、pointer head或候选token读出；它不是某一种训练损失的同义词。也不是所有主流候选都基于Qwen：Laya的ModernBERT／mmBERT、GLiClass的不同编码器和Strands的Gemma分支都应保留。`Base`、指令版、视觉版与不同版本的同名模型不能互换。

| 候选／当前核查起点 | 适配对象与开放程度 | 48GB Mac上的选择边界 |
|---|---|---|
| 普通监督分类器、冻结embedding＋小分类头 | 标签稳定、状态短时可直接训练；模型小、成本容易量清 | 必须有的任务基线。固定标签头无法天然接收任意新路径，但可用请求＋候选配对做条件判断；不是只能用于简单关键词 |
| [Laya](https://github.com/NandhaKishorM/laya) | English421M／multilingual322M；encoder＋决策头；官方有全参／冻结encoder、CE／RLCD、MPS训练与校准接口；Apache-2.0 | 中文路径判断可作为便宜首轮候选。优先小规模真实数据对照，不能从公开typed-decisions成绩推定企业效果；Mac配方见旁页 |
| [GLiClass](https://github.com/Knowledgator/GLiClass) | 动态标签／描述条件化分类；不同代际有32.7M小模型、多语种encoder与更大decoder模型，训练代码和权重可用 | 对固定与动态标签均是实质候选；需按精确版本检查多语种能力、读出和训练接口。公开train.py的随机切分不能替代企业分组／时间切分 |
| [Kev](https://github.com/jaredpalmer/kev) | 0.8／4／9B为Qwen3.5-Base＋LoRA与pointer head；27B为Qwen3.8-27B全权重版本；训练、校准和模型卡较完整 | 0.8B或4B可作需更强上下文理解时的候选；MPS训练与MLX服务是两条实现。9B需验证训练余量，27B原精度权重已超出48GB，不是本机首轮方案 |
| [Strands Decider](https://github.com/strands-labs/strands-decider) | 当前Qwen3.5-2B-Base分支及四种Gemma4指令底座分支；LoRA＋pointer head，版本有多seed合并与后校准；原料有未完整公开部分 | 已有MLX推理不等于MLX训练／校准；官方训练recipe以NVIDIA环境为主。Qwen视觉继承与真实图像适配不同，Gemma发布分支为文本，不能全家族合称多模态已训练 |
| [Mapika Decider](https://huggingface.co/Mapika/decider-2b) | Qwen3.5-Base的2B／4B等分支；候选字母logit读出；监督阶段与后续RL／视觉阶段按版本区分，代码与注册数据源可查 | 2B v12与历史v10／v11、4B不是同一个训练产物；GGUF推理不提供后训练路径。先核查可继续训练原artifact的代码，再判断是否值得迁移到Mac |
| [CLM](https://github.com/Contrastive-LM/CLM) | 冻结LLM编码器＋可训练state/action投影头，以对比目标适配候选选择；公开主路线为Qwen3-8B编码器 | 候选可复用时有吸引力；小head不等于无需8B编码器。相对排序不能发现所有候选均不合法，仍需绝对适用性／拒判和候选召回验收 |
| [Clef／Clef-Flash](https://huggingface.co/Cloudflare/clef) | Qwen3.8-27B／Qwen3.5-9B带视觉骨干＋joint schema head；开放权重／推理，原始完整训练数据未开放；有社区训练桥接 | 更适合作为需要图像时的推理／技术候选。不能把通用VLM LoRA命令当定制schema head的完整训练；Mac训练链路的已测与未测部分见平台核查 |
| [Perplexity Decider v1.3／Flash](https://huggingface.co/perplexity-ai/pplx-decider-v1.3) | Qwen3.8-27B／Qwen3.5-4B；共享状态、定制joint读出；开放权重与推理，完整原始后训练材料未据此建立 | Flash4B推理可列候选，但不能因尺寸可放入内存就称公开配方可在Mac续训；默认因果LM读出不等价于该模型的协议 |
| [Intern-Decision](https://github.com/InternLM/Intern-Decision) | Qwen3.5指令检查点；固定回答骨架、决策marker的causal CE；冻结vision／projector并训练语言骨干；源码和权重分开发布，原训练数据不完整公开 | 官方配置不是现成LoRA，当前训练实现要求Linux／CUDA／XTuner。把4B推理放入48GB不能证明可原样全语言参数训练；新增LoRA需验证marker与视觉链路 |
| [SII-Decision](https://github.com/amazingljy1206/SII-Decision) | Qwen3.5指令版4B／27B；第一token候选读出，同底座思考分布蒸馏；现有代码、训练数据、LoRA与Full发布。Full只更新与LoRA相同的指定语言线性层，非每个参数 | 4B值得保留为不同信号路线；提供的4／8GPU训练wrapper与4090推理脚本不能称单Mac已可复现。LoRA发布为合并权重，继续训练前核查起点及保存格式 |
| [Chinese-Jev](https://github.com/gulucaptain/Chinese-Jev) | 已有encoder训练／数据构造代码，推荐Laya multilingual兼容bundle；CJ数据已发布但混合来源许可；General／行业权重仍列计划发布 | 中文研究参考不等于已有可下载中文行业检查点。当前可验证的是代码与数据合同，不能把社区底座适配称为复现论文原检查点 |
| [Koa Decisions](https://www.salesforce.com/news/stories/koa-decisions-salesforce-decision-models/) | 供应商生产组件与论文方法参考，原企业数据及部署检查点不公开 | 主要借鉴原子标签映射、匹配服务评估和状态合同；不属于现成的本地开放权重训练方案 |

上述模型的代码／权重许可与训练来源许可分开。Apache-2.0卡片不能自动覆盖混合训练语料；某个家族含研究用／非商业来源时，需按精确artifact解释，不能用另一个同家族版本代替。

**条件性选择：** 标签固定且低成本基线已达标，就采用小分类器；需要候选描述／状态语义且预算有限，比较Laya／GLiClass；复杂组合、长政策或encoder稳定失败，再有限增加0.8–4B的pointer／token读出候选；确有图像证据需求，才进入多模态分支。只有可复现的独立领域增益足以支持扩大模型和训练方法，不按参数量、发布时间或通用榜单预定冠军。

## 4. 真实数据应该怎样变成训练信号

每个标注单位是一项案件中**决策前可见状态**：请求／相关历史、已确认字段及来源时间、未知字段、当前路径与owner、已完成动作、候选路径版本、四项判断、支持证据及业务允许的替代答案。用于事后标注的结果不能泄漏到当时输入；未来用户发言、最终退款结果、最终转化不能作为决策时特征。

| 信号 | 适合怎么用 | 主要风险与检查 |
|---|---|---|
| 业务规则＋人工裁定的硬标签／允许集合 | 首轮CE／BCE或候选排序监督；保留证据、分歧和版本 | 既有人工路由也可能错；复合诉求不能硬压成唯一类别，未加载／未采用不自动是假例 |
| 多评审者分布 | 表达定义明确但允许分歧的判断；标注者与评审条件固定 | 分歧可能是合同不清或缺证据，应先修定义，不能简单平均掩盖冲突 |
| 教师概率／思考后的分布 | 将较强或较贵判断压到便宜读出；保留教师版本、可见输入和计算预算 | 教师一致率不是业务真值；同模型自蒸馏也会巩固错误。原始logit／概率、重复采样频率与自报confidence不是同一种信号 |
| 工具回执／案件结果 | 核查执行和构建可程序验证标签；必要时用于策略改进 | 结果可能延迟、缺失或受人工干预及历史策略选择影响；只有被执行动作的结果，不足以识别其他动作的效果 |
| 合成反例／公开路由集 | 定向覆盖缺状态、否定、候选缺失、规则变化，及管道调通 | 不能替代自然流量总体；不得把公开任务已见过或模板同源的高分当迁移证明 |

先按客户／案件／会话／时间及任务来源分组，再生成候选配对、改写和翻译。同一案件的相邻轮次与所有派生正负例同组。至少区分Train、Dev、Calibration和最终Test，保留最近时间段及未见路径／新政策单独压力测试；基线特征、样本重加权与hard-negative挖掘仅使用训练／开发部分。

训练集可强化少数高代价错误，评估仍需自然流量或已知抽样权重。将确定的错误触发列为负例；未标注、候选未被执行或结果尚未成熟应保留unknown，不强制填false。人工评审模型分歧时，应隐藏模型身份并保留一致样本的抽查，否则只有错题复核仍不能估计总体正确率。

## 5. 用匹配对照选择训练方法

首先跑当前生产系统、简单监督／embedding基线和候选模型原版，提供相同状态、候选与证据。若补齐状态或精简候选已经解决问题，就先采用该改动。确认有可学差距后，用同一底座及数据比较监督后训练；RLCD、Brier项、蒸馏、LoRA／全参分别是条件扩展，不一次同时改变读出、损失、数据和服务预算。

本轮方法核查的细节和争议见[训练目标审查](decision-model-posttraining-method-audit.zh-CN.md)。交叉熵是清晰监督任务的有效起点，严格适当目标并不免除领域校准，先思考后蒸馏也不免除教师正确性核验。稀疏业务奖励需要独立的结果口径、策略选择与反馈归因；不能先规定要用RL，再把所有案件成败改写成局部路由奖励。

| 已有信号与任务 | 优先比较 | 什么时候才扩大方法 |
|---|---|---|
| 完整可信标签，能从可见证据作有限答案判断 | 同底座CE／BCE或候选排序监督；与简单分类器、原版模型匹配比较 | 有独立剩余错误时，再比较Brier项、可训练范围、对比反例；不默认RL会更好或更差 |
| 可靠教师／重复思考后的分布 | soft CE／KL蒸馏；SII式reasoning-to-readout是实现参考 | 教师的领域正确性、独立金标和成本均可查；不能仅最大化与同一教师的一致率 |
| 先计算或推理才能判断，且值得承担推理开销 | 保留强生成式推理基线；参考[PRDO v2](https://arxiv.org/html/2609.38850v2)的逐推理proper-score优化 | 最新v2与旧RLCD两阶段不是同一配方；匹配训练及推理预算，并检验整体准确率和选择性排序的取舍 |
| 只有被选动作的正误反馈 | 先核事件语义、选择策略、支持和缺失；CAPS仅作满足其设定后的候选 | CAPS金标模拟日志不证明退款／转人工的因果结果；要学业务策略，另有反事实识别或线上实验要求 |
| 目标是校准和拒判，而非新增判别能力 | 固定权重后，独立Cal-fit拟合温度，Cal-policy选完整回退策略 | 没有足够样本或发生分布迁移时，收窄自动接受范围并重新验证；温度不是新准确率或风险保证 |

先采用小规模对照：一个cheap基线、原版候选及对应训练版；明确剩余错误后才增加第二条模型／方法路线。在Dev上预先限定搜索次数与总训练预算，负结果一并保留。最终冻结一个候选与预先命名的基线，才打开Test。若需要学习曲线，使用按组嵌套的训练子集；多seed测训练波动，不替代新增独立案件。

校准与拒判是发布前独立步骤：使用未参与权重更新／方法选择的Calibration数据拟合温度及阈值；再用Test报告自动接受覆盖率、被接受错误、人工回退质量与漏掉的重要案件。`none`是一个语义答案，低confidence是选择性回退条件，二者不能合并。每候选判断也应在请求层汇总错误，不能把多个候选当独立案件。

## 6. M5 Pro 48GB怎样落实

48GB可以支持有意义的小模型实验，但模型能推理、LoRA参数少、甚至一次训练成功，都不保证同一训练配置的梯度、校准、合并和服务行为正确。先做真实权重的短输入前向／反向、数十次更新、保存重载和概率比对；观察峰值内存、swap、温度与吞吐，再扩到完整训练。固定后端、精度和模板，不能用另一个GPU／MLX后端的校准值直接宣称相同风险。

Laya／GLiClass等encoder较适合首轮；Laya官方MPS full／head训练与LayaStudio MLX LoRA各有真实实现，不把MLX运行时本身当trainer。0.8–4B decoder候选在短序列、参数高效更新下可作工程验证对象；9B与多模态custom head需额外余量和operator验证。27B BF16权重约54GB量级，已超48GB，4-bit推理可用不代表其原始训练配方也可迁移。

具体安装、版本、数据格式及校准保存见[Mac起步配方](decision-model-posttraining-mac-recipe.zh-CN.md)，平台和发布artifact差异见[平台核查](decision-model-posttraining-platform-audit.zh-CN.md)。硬件只是资源边界；当前缺少真实数据时不创建空实验工程，不把下载模型或通过工程测试记成业务进展。

## 7. 从离线判定到生产验收

| 门槛 | 必须留下的证据 | 未满足时怎样处理 |
|---|---|---|
| 问题与数据 | 一种重复失败／成本瓶颈、明确负责人、数据授权与脱敏边界、规则／候选版本、标签仲裁依据 | 继续诊断／标注，不训练更大模型 |
| 可学习性与工程 | 匹配基线、真实梯度更新、保存重载、来源／切分／模板／依赖／权重版本及资源日志 | 修输入、数据或实现；不把运行成功当效果 |
| 独立领域增益 | 冻结Test上关键错误、覆盖、校准、完整成本及按案件计算的不确定性；达到预定最小有用差异 | 保留负结果；小样本不显著不等于等价，是否继续由价值和预算决定 |
| 影子验证 | 模型只提出建议，记录分歧、状态缺失、回退结果；抽查被拒判与未被触发案件 | 修合同和监控，不接管操作权限 |
| 有界生产比较 | 按案件／客户等合适单位分流，避免会话污染；验正确完成、重复联系、错误动作、人工工时和每单成功完整成本 | 依错误上限／停止规则回退到已验证版本 |
| 维护 | 模型／候选／政策／校准独立版本；数据成熟度、状态缺失、拒判率、关键错误、p95和成本持续可查 | 区分输入漂移、模型失效和政策变化；新版本重新通过相应门槛，保留回滚依据 |

只检查升级样本会漏掉高置信错误；只检查已触发／已接受样本，又看不到被抑制案件与候选召回失败。应持续抽样全部自然流量，分别观察语言、产品／客户群、路径、时间与新规则；政策／候选新增或合并时，先检查标签及输入合同，再判断重新校准还是重训。回退策略也要验证，不能假定旧模型／人工在每个低confidence子集上更好。

## 8. 开始实际企业训练前仍缺什么

需要确定的最小输入是：一个业务任务及可重复的失败；一套当前路径和规则；决策前状态及来源；足以审查的授权案件；标签裁定者；现有基线的质量／时延／完整成本；关键错误上限、最小有用改进和训练／推理预算。仅给一批对话、一个模型名或一项转化率都不足以冻结实验。

当前交付是可执行研究路线和来源边界，不包含真实企业标注、目标机安装／训练、独立模型效果或生产A/B。后续在实际环境中按上述门槛形成一个训练实验，沿用现有工作入口；不为了证明某个模型而反向寻找有利样本。
