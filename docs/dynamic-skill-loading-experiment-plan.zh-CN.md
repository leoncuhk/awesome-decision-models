### 阶段0：先验证是否存在可修复的瓶颈

比较当前基线、静态精简/元信息按需读取、人工足够技能集合诊断参考、简单检索加回退。冻结执行器、规则、可见证据和缓存；用一小组真实可授权任务诊断，分别报告自然流量与压力案例。人工参考不改善则先修执行/评测；静态精简足够则不建新加载器；简单检索达标则采用现成组件。只有证明多轮缺载与干扰确实影响任务效用，才展开后续大矩阵。样本量及收益门槛由先导与业务成本确定，不默认40技能、recall .98或固定收益百分点具有通用意义。

### 本次一手复核限定

- Skill Shadowing v2只保留单技能增益至少4个百分点的38个任务—模型对；202库下降为21个百分点。上下文效应不显著不等于不存在，Sonnet分项点估计不低于shadowing。
- Demystifying中precision29.6→3.3同时任务成功36.4→39.3；离线检索未作为执行实验前级。
- Workday的100技能全量0分来自32k溢出；只测24个activation-code检索任务，非业务执行。
- Wix的7.8%来自风险富集1000会话；90.5%只计算技能描述token，覆盖10技能域族，不能外推全流量或账单。
- Dialpad的45.0%为五judge均值；同模型33.8–58.6%，确定性检查90.6%。500合成场景、模拟工具，不代表生产完成率。
- Comparative Retrieval的不同测量使用639/690/875等规模，主检索仅117查询；未测任务完成与延迟。

## 0. 摘要

- **问题**：一家企业的服务 Agent 覆盖**数十个**技能。每轮先把对话路由到一小组相关技能（动态加载），在任务成功率、政策违规和实际计费成本上，是否优于一次暴露全部技能？
- **证据边界**：部分技能库扩大后选择和任务成功变差，但也有检索变差、任务成功不降的结果。上下文、候选混淆与执行能力都需分别诊断；这些来源不能证明本企业需要动态加载。
- **本方案的贡献**：分阶段、预注册的对照实验，并以**理想路由（oracle）诊断参考**作参照。它把常被混为一谈的三类收益（质量、成本、治理）分开测量。
- **最终验收**：任务结果、关键错误约束和完整成本；可接受技能集合的漏载率、回退与误载仅作诊断指标，单一gold技能未必必要或唯一。

## 第二部分 洞见

1. **先诊断瓶颈。** 技能相似度可能影响识别，长正文也可能溢出或干扰；不能从单一研究推断选择始终是主要瓶颈。技能粒度是待检验的变量。
2. **动态加载可能引入漏载。** 当必要能力被排除且无法通过替代技能、扩大检索或澄清恢复时，漏载才形成执行瓶颈。记录可接受技能集合和最终任务结果，而非只看单一gold的recall@k。
3. **收益分三部分，证据强弱各不相同。**
   - *质量*：实验证据中等，没有客服端到端证据。
   - *成本*：描述token可能减少，但需计额外调用与回退。缓存影响取决于实际序列；Anthropic Tool Search保留稳定system/core tools缓存，动态加载并非必然破坏缓存。
   - *治理*：负责人、版本、测试与回滚同样可以在静态加载系统中实现；不要把技能模块化的价值全归给动态加载。
4. **选对仍需执行。** Dialpad是合成场景和模拟工具上的judge评估，不是线上失败率或本系统收益上界。可用人工足够技能集合做本地诊断参考，先判断选择改善能否改变任务结果。
5. **护栏绝不能依赖路由。** 红线、升级规则和身份核验放在由代码强制的常驻核心里，否则一次误路由会连保护一起卸掉。
6. **代码门控是廉价、可审计的精度来源。** 剔除前置条件不成立的技能（权益、订单状态、已生效的设置），在 Wix 的真实流量中把候选砍掉一半以上，不需要任何模型调用。
7. **决策模型是候选路由器，不是默认选项。** 校准结论迁移不到企业自己的阈值上（E35、E37），近似选项下拒判会崩溃（E20）。监督小分类器是必须打败的基线。

## 第三部分 面向企业原型的实验方案

### III.1 企业原型（匿名化）

- **服务**：大型中文消费订阅服务，在多个 IM 渠道上做文字客服，对话中服务与销售混合。
- **技能清单（目标约 40 个），分八类：**

| 类别 | 示例技能 | 已知易混对 |
| --- | --- | --- |
| 账户 | 登录、身份核验、资料修改、注销账户 | 注销账户 vs 取消订阅 |
| 计费与会员 | 购买、续费、支付失败、发票 | 续费 vs 自动续费投诉 |
| 退款与取消 | 申请退款、取消、降级、挽留优惠 | 退款 vs 取消 vs 降级 |
| 订单与预约 | 预约、改期、爽约政策 | 改期 vs 取消预约 |
| 安全与举报 | 举报用户、隐私请求、防诈提醒 | 举报 vs 一般投诉 |
| 产品指引 | 功能使用、服务说明 | 使用方法 vs 故障排查 |
| 销售咨询 | 套餐对比、价格咨询、优惠资格 | 价格咨询 vs 要求折扣 |
| 投诉与升级 | 投诉受理、转人工 | 投诉 vs 退款 |

- **现有系统**：封闭集意图分类器（约 10–15 个意图）、工作流模板和转人工。
- **红线（常驻核心）**：不承诺结果、不擅自打折、强制转人工的触发条件、隐私处理。

每个技能卡包含：描述（不超过一段）、处理流程正文、**工具白名单**、**前置条件**（门控谓词）、以及指向相关红线规则的链接。技能分类和粒度由**业务负责人**在标注开始前确定并冻结。

### III.2 预注册假设

| 编号 | 假设 | 证伪条件 |
| --- | --- | --- |
| H1 | 全量平铺下的 top-1 选择随 K 下降；同等 K 下，易混库比差异库下降得更陡 | K=40 时斜率差异不显著 |
| H2 | 限定加载器（k=5）在 K=40 易混库、独立撰写的查询上达到 recall@5 ≥ 0.98 | 没有任何加载器组达到 0.98 |
| H3 | 端到端，K≈40 时理想路由比全量平铺的 pass^4 高 ≥5 个百分点 | 配对差 < 3 个百分点 |
| H4 | 开启提示缓存后，路由方案的计费成本优势不到其 token 优势的一半 | 计费比 ≈ token 比 |
| H5 | 在话题切换对话中，带滞后（hysteresis）的逐轮路由优于按会话一次路由和无记忆的逐轮路由 | 无差异或结果相反 |
| H6 | 确定性可执行性门控减少对应被拦截技能的选择，且不降低任务成功率 | 成功率下降，或被拦截选择没有减少 |

### III.3 分阶段实验（由便宜到昂贵）

**第 1 阶段：只测路由，用公开替代数据**（数小时，只有分类调用，本地模型）

- **技能库**：把 ABCD 的 55 个子流程转为技能卡，K ∈ {10, 30, 55} × {差异库, 易混库}。易混干扰项是由另一位作者或另一个模型改写的近重复技能，外加 SGD 中的同类服务。中文部分加入 MASSIVE zh-CN 场景集。
- **查询**：真实对话轮次（金标 = 子流程）。拒判样本来自 CLINC 域外样本，加上按 E20 协议**删去金标技能构造的困难负例**。
- **对照组**：
  - R0：LLM 从全部 K 个技能中选
  - R1：基于元信息的渐进式披露
  - R2：BM25 + 嵌入
  - R3：R2 + 每个技能的离线意图查询
  - R4：类型化决策模型，选择题加"都不是 / 升级"
  - R5：小型监督分类器（**基线**）
  - R6：两级路由，先类别后技能
- **指标**：recall@{1,3,5,10}；风险-覆盖曲线与 AURC；金标缺失时的错选率与金标存在时的误拒率，分开报告；ECE **和**正确性 AUROC；p50/p95 延迟；每千次路由成本。
- **统计**：每格约 1,000 条，按对话聚类做配对 bootstrap，组间用 McNemar 检验。阈值在校准集上用 Learn-then-Test 拟合，在留出集上报告。
- **停止规则**：K=55 易混库上若没有任何组达到 recall@5 ≥ 0.98，先重新设计技能粒度或增加回退路径，再进入第 2 阶段。

**第 2 阶段：只测路由，用企业自己的对话轮次**（数天标注，私有，离线）

- 从真实对话中抽取约 1,500 轮，按类别分层，并对易混对和话题切换过采样。压力集单独报告；另保留自然流量校准／测试集用于阈值、升级量与总成本验收，或预注册可识别的抽样权重。训练、开发、校准、测试按会话与时间隔离。两名标注员独立标注金标技能，并标出"技能存在 / 缺失"；报告一致性，分歧经裁定。
- 在企业自己的技能卡上，K ∈ {10, 20, 40}，跑与第 1 阶段相同的各组。这是对 H1、H2、H6 的未污染中文检验。

**第 3 阶段：端到端，模拟用户**（计算量最大的一档）

- **评测框架**：为约 40 个企业技能编写 τ 风格任务，配模拟工具和数据库状态。先在合并后的 τ-bench 领域上做试点，把框架调通。
- **对照组**：
  - 全量平铺
  - 全量平铺加提示缓存（仅用于成本比较）
  - **理想路由诊断参考**（逐轮提供经独立标注的全部必要技能集合；保留相同权限、证据与执行器。多技能依赖须完整，不能只给技能类别；不宣称数学上界）
  - 路由：第 2 阶段最佳加载器，k=5，加可执行性门控和常驻核心
  - 路由去门控
  - 路由去粘滞
  - 渐进式披露
  - **A/A**（全量平铺跑两次）
- **控制**：各组使用相同模型和相同技能文本；全量平铺组打乱技能顺序；固定模拟器和随机种子；人工审核约 50 份对话记录。
- **指标**：pass^4、政策违规率、每个已解决任务的计费成本、每轮延迟、失败归因（加载器 vs 执行）、目标切换后的恢复。
- **统计功效**：300 个任务 × 4 次是初始预算，不保证检出特定差异。pass^4以任务为独立单位；先用独立pilot估计基线、配对不一致率及任务相关性，预定alpha、power和多重比较规则，再做任务级配对功效模拟决定样本量。
- **停止规则**：
  - A/A 波动超过（理想路由 − 全量平铺）的一半时，先修评测框架。
  - 理想路由 − 全量平铺 < 3 个百分点，**且**计费成本收益 < 20% 时，质量和成本都不足以支持动态加载，只能基于治理理由决策。
  - 仅在理想参考完整且其相对平铺差异的置信区间下界明确为正时计算路由效率 η；否则报告不确定。η =（路由 − 平铺）/（理想 − 平铺）< 0.5 时，回到第 2 阶段；不得把不可靠参考当作否决依据。

**第 4 阶段：影子运行，然后灰度**（生产环境，需明确批准）

- **影子运行**：路由器与现有分类器并行，不影响用户。抽样分歧样本交人工复核，每周检查漂移。
- **灰度**：约 5% 流量；升级率、投诉率或红线触发任一超标即自动回滚。
- 每次更换模型、服务链路或校准器后，重新验证阈值。

### III.4 效度威胁

| 威胁 | 控制手段 |
| --- | --- |
| 技能作者自己写评测查询 | 用真实用户轮次，或由独立人员撰写查询 |
| 技能描述质量 | 各组文本一致；措辞影响单独测（SGD-X 方式） |
| 公开替代数据被污染 | 只解读同一轮内的配对差；私有数据上的第 2、3 阶段才是决定性的 |
| 提示缓存 | 始终报告开启缓存时的计费成本 |
| 模拟器和评审偏差 | 固定模型、人工审核、报告一致性 |
| 阈值不能迁移 | Learn-then-Test、留出集复核、漂移后复核 |
| 分叉路径（多重比较） | 预注册 H1–H6、各组、指标和停止规则；公开负面结果 |

### III.5 仍需人类判断之处

- **技能分类与粒度**：这是业务和责任边界，证据表明它对结果起主导作用。
- **误路由与升级人工的相对代价**：决定风险-覆盖曲线上的工作点。
- **常驻核心包含哪些内容。**
- **金标标注与上线晋升决策。**

## 第四部分 实验拟得出的结论

方案的设计目标是让**每种结果都对应一个决策**，包括无差异的结果。

| 观察结果 | 结论 | 行动 |
| --- | --- | --- |
| H2 成立、H3 成立、η ≥ 0.7，且实际路由相对平铺的任务成功、政策违规和完整成本满足预定验收及区间要求 | 在该规模下动态加载提升服务质量，路由器拿到了大部分可得收益 | 采用"路由 + 门控 + 常驻核心"，进入第 4 阶段 |
| H2 成立、H3 不成立（理想 − 平铺 < 3 个百分点）、H4 显示真实计费节省 | 收益在成本，不在质量 | 仅当业务量下节省有意义时采用；保留"全量平铺 + 缓存"作为回退 |
| H3 不成立且没有成本收益 | 当前实验未显示动态加载的质量或成本价值；执行是否为根因仍需诊断 | 停止扩大加载器投入，检查执行、证据、评审及统计功效；治理可单独实现 |
| 易混库上 H2 不成立 | 当前方案未达标，原因尚未识别 | 分层诊断标签、可见证据、候选召回、模型和技能粒度；按已证实原因修复，重跑第 1、2 阶段 |
| R5（监督）≥ R4（决策模型） | 这个路由器不需要托管决策模型 | 用本地小分类器；技能分类变动时再复评 |
| R4 > R5，且留出集阈值有效 | 类型化决策模型值得其成本和依赖 | 采用，并在每次发布时重新验证阈值（E19、E38） |
| H5 成立 | 话题切换需要有状态的路由 | 上线滞后机制，并把目标切换测试加入回归集 |
| H6 成立 | 代码门控可能提供无需新增模型调用的收益；计入取状态和维护成本 | 每张技能卡强制填写前置条件 |

**不预设胜出结果。** 原有3–8个百分点等预期没有本地先导依据。以下阶段是条件性备选；先完成阶段0价值诊断，再决定是否展开。
