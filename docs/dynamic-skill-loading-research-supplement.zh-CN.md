# 动态技能加载：补充研究、数据入口与版本边界

审阅日期：2026-11-13。[价值复核](dynamic-skill-loading-value-review.zh-CN.md) · [实验方案](dynamic-skill-loading-experiment-plan.zh-CN.md) · [REFLEX与轨迹](agent-control-reflex-trajectory.zh-CN.md)

本轮选择能改变实验设计的八项资料，不继续堆叠模型排名。前述技能遮蔽、REFLEX、真实应用与反例保留在原文档。本页为来源审阅；没有安装基准、下载客户数据、运行模型或独立复现实验。固定代码提交用于定位文档和契约，不等于权重、数据包和评测运行均已固定。

## 阅读顺序：先确定业务结局，再研究选择器

1. **ABCD＋τ-bench**：定义流程、必要状态和真正完成的业务结果。
2. **SGD-X＋AgentChangeBench**：建立措辞变化与中途改意图的压力集。
3. **Skill++＋早期商业skill routing研究**：检查新增、移除或修改技能时旧流量是否退化。
4. **AppWorld**：需要跨应用依赖时再使用；不是所有客服实验都需要它。
5. **Hyper-τ**：已有稳定验收后，研究如何从散落的业务证据构建Agent，勿直接升级为第一阶段大项目。

## 八项资料及其改变的实验设计

### 1. ABCD：业务流程不等于意图标签

[官方仓库固定版本](https://github.com/asappresearch/abcd/tree/6b8700ce67c6b37b062dd7a60abc76d7ef832a97)提供10K以上人对人对话、55意图与多步骤动作／指南。它是为研究采集的对话资料，不能称真实生产日志。审阅README与目录，未审计全部样本。仓库MIT；使用具体文件时保留其随附条款。

**实验启示（编者）**：零售退款案例不能只问“是否退款意图”；需要把身份核验、订单状态、政策判定和后续依赖一起标注。先映射可接受动作集合，再考虑映射技能卡。重放已有轨迹能测选择，不能直接测改变选择后的业务结果。

### 2. τ-bench / τ²：用最终状态检验是否完成

[固定README](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/README.md)、[评估契约](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/docs/evaluation.md)。MIT，已审阅README、评估文档与`src/tau2/data_model/tasks.py`相关字段。当前2.0含语言、数据及语义沟通裁判变化，不能将2.0与1.0.1分数直接拼接。

`actions`记录一条可完成任务的参考路径；默认`reward_basis=[DB, COMMUNICATE]`，动作匹配可以只是诊断，是否计分由任务契约决定。**实验启示**：保留固定领域、任务、语言包、裁判和模拟用户；允许不同有效路径，不因没调用指定skill就判失败。电信场景适合测用户与Agent共同改变状态；客服同时检查最终订单／账户状态和必要信息交付。

### 3. SGD／SGD-X：同义描述和未见服务

[固定仓库](https://github.com/google-research-datasets/dstc8-schema-guided-dialogue/tree/e852981ae34990f4358979625854259302feaa78)。审阅README的schema、frames、数据生成和许可。SGD由模拟器与付费众包共同生成；SGD-X每个schema有五种表达变体。数据为CC BY-SA 4.0；不能将衍生数据自动改授本仓MIT。

**实验启示**：保留业务含义，仅改技能名、描述、选项顺序；分别测路由、参数收集和任务结局。按服务而非随机轮次划分未见测试。此数据提供接口与对话状态，不自带完整企业SOP和权限合同；用它测稳健性，不能据此宣布业务可上线。

### 4. AgentChangeBench：把“承认新目标”和“完成新目标”分开

[论文v1](https://arxiv.org/html/2510.18170v1)、[代码固定版本](https://github.com/Maniktherana/AgentChangeBench/tree/22f2cec4ac0ec6c4d68b2fab856da78054c8980b)。已审阅方法与指标定义、README；仓库标MIT，未逐项核样本。论文摘要与正文的规模表述不同，本页不导入任务总数成绩。

GSRT分承认、相关工具与结果三个时间点；其“恢复”分类仅要求承认且不转人工，并不要求新目标完成。TSR是多项加权分，不等同严格任务成功。**实验启示**：订阅服务从“咨询退款”改成“保留账户但关闭续费”后，分别记录检测、首次正确动作、完成所需轮次与实际秒数；转人工是否合理由业务规则判定，不能一概算失败。

### 5. Skill++：新技能入库也是一次模型行为变更

[Skill++ v1](https://arxiv.org/html/2611.00544v1)。已审阅方法、实验和局限；新预印本，未定位到可确认的作者实现版本／完整数据许可，因此作为设计参考，不提供复现承诺。该方法保持router不变，只在技能进入目录时，依据正文及相似旧技能改写名称、描述和排除范围；任务是文字技能选择，不等于业务执行。

**实验启示**：固定旧请求回归集，逐批加入“退款申请／退款进度／撤销申请”等相近技能，分别测旧流量、新流量及完整技能集合召回。增设“只改描述”的廉价基线；若它解决问题，就没有证据支持重训decision model。新描述必须忠于正文，不能为匹配测试查询而夸大能力。

### 6. 商业skill routing的历史研究：订阅和资格会变

[Neural model robustness for skill routing，2021](https://arxiv.org/abs/2103.03373v1)。本轮仅核摘要与元数据，不导入数值结果，也未确认公开实现／数据许可。该工作讨论商业对话系统中的skill订阅变化、共享intent/slot以及设备上下文条件。

**实验启示**：不要把“skill routing”视为2026才出现的新问题。企业新增服务、下线接口、不同租户可用能力变化，都应进入测试。语义相关但当前不可用的技能先由状态／权限过滤；比较数据增强、小分类器和简单规则，再判断自然语言决策模型是否必要。

### 7. AppWorld：跨应用依赖与副作用

[固定README与许可说明](https://github.com/StonyBrookNLP/appworld/blob/42b5bcf3cd334fee33f0c37c02070a9f5807add5/README.md)。审阅执行环境、评估和许可分区；未运行。公共工具代码Apache-2.0；包含任务、API实现和测试的受保护bundle附加加密再分发要求，不应将解包内容提交到本仓。

**实验启示**：内部服务台跨邮箱、日历和业务系统时，top-1技能命中不保证前置读取、对象定位和写入依赖完整。用最终状态／测试验收并检查无关对象是否被修改。AppWorld是模拟应用世界，其强项是可检验副作用；它不能直接替代真实客户任务和当前服务权限。

### 8. Hyper-τ：从业务资料构建系统，而非只调router

[固定仓库](https://github.com/sierra-research/hyper-tau-bench/tree/6e9f34c685d40fa7a9f5935d8970af6fd9d5f118)、[Sierra介绍](https://sierra.ai/jp/blog/hyper-t-bench-evaluating-agents-that-build-agents)。MIT；本轮审阅README的构建／执行边界、发布任务及预算要求，未核查全部任务bundle。开发Agent从政策、对话、截图等材料构建可执行客服Agent，再以留出客户任务评分；外层构建与内层服务是两种成本。

**实验启示**：适合后续研究“技能卡是否忠实地反映真实SOP”。可先借鉴其需求证据包和封存测试思路，不必立刻运行完整外层。保留建模、维护、服务调用三项成本；不要用自动生成skill的数量或工具测试通过替代最终服务能力。

## 与业务实验的对应

| 业务问题 | 首要资料／最低成本验证 | 只有何时才升级 |
|---|---|---|
| 零售退款、订阅取消的入口与后续依赖 | ABCD＋固定状态合同；比较当前流程和静态分组 | 漏载必要流程可归因地造成任务失败 |
| 客户中途改变目标或暂停当前流程 | AgentChangeBench的分段指标＋τ任务最终状态 | 事件触发重选明显优于保持／简单状态机 |
| 新增同类服务后旧流量误路由 | Skill++思想＋SGD-X表达扰动；先修描述 | 相同描述质量下简单router仍有可测差距 |
| 跨应用办公／内部服务台 | AppWorld最终状态与副作用验证 | 候选依赖复杂到静态分组不够，且有足够真实需求 |
| 资料零散、业务规则尚不清楚 | Hyper-τ证据包思路，先澄清SOP | 规则和标签稳定后才测加载器，避免优化错误合同 |

所有“实验启示”和应用对应都是本次编者设计推断，不是来源作者已证明的企业效果。上述八项已经覆盖本分支当前最重要的额外维度：业务状态、变更目标、表述稳健、目录演化、依赖完整与构建成本。新增资料应以能否改变实验条件为准；没有对应问题时不扩大实验范围。
