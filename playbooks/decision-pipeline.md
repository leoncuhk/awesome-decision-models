# 通用流程：从决策合同到上线验收

更新：2026-11-23。目标：**用企业自有数据改善一个明确的决策问题，在质量、风险、算力与完整成本约束下选出可实施方案，并验证相对现有方案的增益。** 判断依据见 [problems/](../problems/)；场景手册见[多模态后训练](multimodal-posttraining.md)与 [skill 路由选择器](skill-routing.md)；逐模型事实见[模型卡](../docs/models.md)、[证据台账](../docs/evidence.md)与[来源登记](../docs/sources.md)。

现状：研究与协议准备阶段；没有目标企业数据、训练结果或生产对照；目标训练机 M5 Pro 48GB 未运行。下文分别标明来源报告、公开产物核查与实施建议。

## 本轮选择：先完成一次可判定的领域适配

2026-11-23重新审视：文献与候选已经足够支持首轮实验设计；剩余决定性缺口是目标机训练回执、可信企业标签和独立业务对照。以下是**实施优先级**，不是尚未测得的效果排名。

| 条件 | 首轮建议 | 为什么；何时换方案 |
|---|---|---|
| M5 Pro 48GB为固定训练机 | 先做轻量监督基线；重点验证Unsloth MLX＋受支持Qwen3.5-4B的直接CE／LoRA；2B作为资源备选 | 有Mac源码路径，尚无本机运行。先验依赖、真实反向、峰值、head保存重载和服务一致性；不支持时保留encoder／短标签MLX方案，不把推理量化包当训练方案 |
| 可使用CUDA，要求专用检查点领域续训 | 优先核Adjudex4B v7的native全参续训，并列Chinese Pointer4B与Valen4B的LoRA路线作预算匹配比较；Kev保留工程基线 | 先按下方固定覆盖表完成训练资格准入；通用分数与训练便利性是不同理由，不能只选熟悉项目。全参与LoRA总预算不同，横比属于系统选型 |
| 数据允许上云且服务资格匹配 | GLiDE训练API或百炼，与上述本地方法做完整费用／效果比较 | 必须确认精确模型、导出／部署、账号及数据合同；托管训练不满足本地权重控制的所有需求 |
| Lemon／Strands／RSI等新增产物 | 先作原版对照、数据或实现参考；有明确缺口再做适配 | Lemon完整trainer尚未定位；Strands新代码已补合并checkpoint续训，但精确版本／CUDA仍需准入；RSI原数据缺口不能由榜单消除 |

**首轮交付四项：** 冻结的业务合同和分组数据清单；目标机前向／反向／保存重载记录；原版、轻量监督、一个小模型直接适配的配对结果；最终接受／转交策略的风险、任务成功与完整成本。原版属于每个训练臂的必备对照，不能因“三组”省略。

先挑一个高频且可裁定的决策点，例如“当前状态应加载哪些适用技能、是否需要补证”，不默认同时训练领域、下一步动作、退款资格和合规。数据预算按标注分歧、稀有错误与学习曲线分批增加，不预先保证固定几百条足够。

若直接适配的剩余失败是标签覆盖，下一步比较经审核教师增强；若是概率问题，先单独校准／改完整门控；若是缺证据，先修取证；若确需生成推理，再比较PRDO。没有训练增量、未达风险约束或总成本反升，都可作为停止结果。实际训练沿用`improve/post-training`及业务项目入口；本仓继续维护问题、协议和公开证据。

### 4B候选覆盖：先完整筛选，再缩短名单

**范围固定于2026-11-23核查的DI0.4.1／11月21日快照**：将346个配置与容量元数据对齐，按**总驻留参数3–6.5B**筛出69行；这是近4B容量筛选，不代表69个独立架构。排除名称中的0.4B／74B误匹配；Gemma E4B约8B总参数、26B-A4B也不混入。62个HF发布物取得卡片与完整siblings，7项存在定位／访问缺口，逐项列在[覆盖表CSV](assets/4b-candidate-audit.csv)。这不是全网穷尽或所有69个trainer完整审计；对18个此前遗漏的靠前候选另做卡片／许可／文件清单与必要源码审查，并复核Adjudex及既有候选；低分行只作初筛。

榜单中的Adjudex57.25为第15组，Starlord56.94及SingVL56.75为第16组；规则按各组首项锚定，因此两模型相差不到0.9也不必同组。分组不是显著性检验；原版分差不等于企业适配增量，详见[固定成绩记录E46](../docs/evidence.md#e46)。以前仅比较Kev／Valen／RSI／Perplexity的范围不足，不能据此称Valen为全体4B最优。

| 候选层次 | 本轮处理 | 尚缺的证据 |
|---|---|---|
| Adjudex4B v7 | 高分且随包有全参CE／可选Brier、`initial-checkpoint`、读出保存及恢复代码，优先做训练链准入 | 代码来自Perplexity v1.1，CLI仍有27B默认值；须匹配4B、attention／pooling及开发参考预测。不是现成LoRA／M5方案，未实跑 |
| Chinese Decision Pointer4B | 中文方向的实际LoRA候选；已核合并检查点加载、保留pointer head、新LoRA及head保存链，Full53.96 | 必须`--readout pointer`（默认letters）、转换prepared数据、核原训练数据权利；原榜配置为顺序／逆序两次平均，非单次开销，无M5训练证据 |
| Valen4B | 保留为明确native LoRA流程的对照，不再因工程方便称效果首选 | 企业真实适配与目标硬件；MPS统计兼容问题 |
| Starlord／SingVL／KnowLine | 保留高分原版资格调查；Starlord权重NC-ND，SingVL许可证及trainer未核，KnowLine5.5为Gen5同权重的短输入重读变体 | 商用／衍生许可、完整trainer及精确榜单版本身份，不把最新卡片和旧成绩混用 |
| Perplexity Flash／其他高分推理包 | 作为可访问且许可合适的原版对照；没有trainer不等于永远不能训，但补工程须计成本 | 专用头、数据转换、真实反向、恢复／导出链 |
| RSI／其他公开训练项目 | 根据协议和资源缺口选择第二阶段候选，详覆盖表 | 不因代码目录名有train就认证原生检查点续训；原配方和自有数据适配分别核 |

**不再随着新名字直接换首选。** 研究候选进入实际训练和最终采用须逐步满足：属于目标规模／输出合同；固定产物可取得并有适用权利；原生训练或明确移植路径；目标机前后向及保存重载通过；最后才在同一企业留出、预算和风险合同上替换现用方案。新模型、未上榜的SII／Jeff／Lemon、以及异构Vega拟合头可保留研究入口，没有同协议分数就不补猜排名。

<a id="when-to-use"></a>
## 0. 什么判断适合决策模型

| 情形 | 先试 | 关键检查 |
|---|---|---|
| 精确算术、日期、硬规则 | 代码／规则，把结果作为输入交给语义判断 | 预处理单独测试 |
| 标签稳定、样本充足 | 常规分类器／SetFit／多语 encoder，与决策模型并列 | 灵活性是否值得额外成本 |
| 候选少、条件细 | 文本—问题—选项联合读出（Kev、Nimble 类）＋托管对照 | 否定、例外、缺证据、顺序变化 |
| 候选多且可复用 | 双塔（CLM）或 reranker | 缓存经济性；全部候选都错的情形 |
| 交给模型／工具／人 | 路由与 learning-to-defer | 实测执行者互补性，而非通用难度 |
| 动作改变结果 | contextual bandit／因果方法 | 历史日志只观察被选动作 |

设计目标可写为 \(a^*(x)=\arg\min_{a\in A_{allowed}(x)}\{\mathbb{E}[L(a,Y)\mid x]+C_{exec}(a)+C_{delay}(a)\}\)。这是设计表述，不代表模型能估计每一项。部署回路保持：**证据 → 确定性检查 → 语义判断 → 策略／风险门 → 已核实结果**。
**当前实施起点：** 用可信领域标签比较简单监督基线、候选原版和小模型直接适配；CE／BCE是起点，硬标签与有依据的软目标按任务选择，概率校准和完整接受／转交策略另验。先验证可用的小模型，再决定是否增加教师、蒸馏、级联、部分反馈或推理训练。当前没有得到企业效果最优的模型或固定升级链。

<a id="goal"></a>
## 1. 从生产问题定义训练目标

先选一个重复发生、可核对的错误或成本瓶颈，例如漏判必要路径、撤销目标后误触发旧流程、需要补证时贸然执行，或大量简单判断占用昂贵调用。记录当前系统、可见证据、错误代价与任务终态；模型更新只改变其中一个明确环节。

“预期业务收益、证据扎实程度、成本和风险”是合理选择标准，但应落实为：与当前方案相比，完整任务正确完成或关键错误改善多少；相应对照是否匹配目标任务和训练预算；标注、教师、训练、推理、回退及返工的总成本如何变化。尚无目标域测量时，这些是待检验的先验判断，不能填成确定排名。

客服常见特点须在实际任务中核实，不能直接当作四条公理：

| 工作假设 | 必须核实的条件 |
|---|---|
| 很多轮次是读已有证据的分类 | 固定动作集合不意味着证据齐全、判断简单或无需推理；历史／档案／知识必须确实可见且足够新 |
| 标签有噪声，也可能多解 | 区分错误标注、缺事实、真正分歧和多个合法动作；不同情况不应统一平滑成一个分布 |
| 只观察选中动作的结果 | 还要核结果语义、观察窗口、缺失、人工干预及选择策略；“没再联系”不自动等于动作正确 |
| 需要低延迟和概率门控 | 只有实际使用概率做策略选择时，才需验该策略下的风险／覆盖；局部低ECE不保证完整动作安全或任务成功 |

<a id="decision-contract"></a>
### 决策合同：模型判断与业务执行分开

输入是决策前可见的当前目标、必要历史、已确认字段及来源／时间、未知字段、当前流程、已完成动作与候选路径版本。根据具体瓶颈选需要的输出，不要求每个项目都训练以下全部四项：

| 输出 | 标签／证据 | 系统确定性职责 |
|---|---|---|
| 路径适用性 | 相关性与是否满足条件分开；允许多路径、可替代动作及证据不足 | 身份、资格、允许操作和状态新鲜度 |
| 信息充分性 | 缺少哪项事实、应查系统还是澄清 | 字段与来源约束、取数及回执 |
| 冲突 | 客户目标、事实、政策或动作的具体矛盾 | 政策版本、来源权威、显式互斥及退出规则 |
| 优先关系 | 前置依赖、并行、撤销和暂缓 | 冻结的依赖／优先约束及客户明确顺序 |

条件标签可设计为`supported / refuted / unknown / conflicting_evidence`，由代码组合到路径集合；这是自定义合同，不是任何供应商原生保证。`unknown`是业务状态，不等于概率接近0.5；模型可以高置信地判定缺证据。相关性、资格、动作完成、客户获益和因果增量是不同终点。

**合成例：subscription-demo-v1。** 客户说“别再扣费，上次那笔也退掉”；身份、订单与退款状态尚未核实。可同时存在取消续费与退款诉求，当前允许下一步包括身份／订单查询，不能直接执行两个写操作。该虚构合同规定：退款须有显式请求、核实身份和订单且未退过；查询政策不授权写入。客户随后改为“上次已退，我只要发票”时，应重新确认目标及系统状态，终止不再适用的退款路径。八个[合成案例](assets/skill-loading-cases.jsonl)仅解释合同，不是企业训练或效果证据。

最新政策、金额、日期、权限和精确计算应由版本化证据与代码提供。训练应学习稳定的语义／条件边界；不能用更新权重补偿owner丢失、过期状态、坏工具或相互冲突的制度。

<a id="method-selection"></a>
## 2. 采纳优先级：先落地哪些算法

默认合同是企业能取得少量至中等规模的可信决策标签／允许集合，处理有限候选的语义／状态判断，并优先低延迟。**下面给出实际投入顺序：1、2是主选路线，3只在保留推理的子任务启用；其余保留为研究储备。** 这是按任务直接性、对照证据、额外数据条件和实施成本作出的采纳判断，不是尚未测得的目标企业效果榜。

<a id="current-decision"></a>
<a id="learning-signals"></a>
| 优先级 | 值得采用的训练方案 | 为什么排在这里；怎样实施 |
|---|---|---|
| **1：默认首选** | **领域直接监督：CE／BCE＋合适底座的参数适配** | 与企业明确标签直接对应；已有同标签预算研究及真实多轮客服实践。互斥类用CE，非互斥命题用相应BCE／多标签读出。LoRA、encoder微调或小头按数据／资源选；有保留能力需求才比较KL／有效replay。先与原版及廉价基线做领域增量对照 |
| **2：标签／质量有缺口时优先加入** | **经核验的教师辅助监督／离线蒸馏：hard CE或soft CE／KL** | 真实企业案例采用带解释的标注，再增加自检并人工审核；对照支持新增critique／计算的价值，不单独证明解释或软概率更优。先审教师错误、覆盖和成本；同一批保留样本比较教师hard与soft。SII的思考到读出、大小模型压缩属于这条路线的不同实现，不占两个排名 |
| **3：推理专项** | **逐推理proper-score训练：PRDO** | 对本就生成推理、按其后分布接受／转交的任务，有多底座受控概率／排序证据；比默认零生成主路增加运行计算。与reasoning-SFT／GRPO＋校准对照，保留准确率退化；零生成路由不启用此项 |

教师标注是监督信号来源，LoRA是参数化，校准／门控／级联是部署层选择；它们不再各占一个“更高级算法”名次。模型大小压缩只在质量可达而服务成本仍有瓶颈时比较；直接适配小模型达标就不要求先训练27B。

**暂不放入当前默认采纳队列，但保留重开条件：**

| 研究储备 | 当前后置的原因 | 何时重开 |
|---|---|---|
| CAPS／chosen-action直接回归 | 原证据是唯一gold类别正误的模拟日志；不是任意满意度／转人工结果，也非唯一正确方法 | 已有语义匹配、有效覆盖和可核噪声的日志；与补标监督及positive-only比较。多动作业务结果改用独立结果模型及相应DM／IPS／DR评价，而非硬套softmax |
| Max式RLAF、环境PPO／GRPO等进一步策略优化 | Drex／Mapika有正面结果，不能永久排除；但存在追加训练／验证选择／辅助任务与公开trainer缺口，尚不支持它们默认优于直接监督 | 策略错误确是瓶颈，且有可验证环境／反馈或可核目标；补等新增数据、等总计算的继续SFT／蒸馏对照及迁移／保留任务验收 |
| 无筛选自蒸馏、多教师连续加权、长程SRD或数据生成器DPO | 不能由模型大、名字新或聚合分高推出标签正确与完整成本收益；还有类别功能丢失、任务不匹配和高算力要求 | 先有明确剩余失败与简单教师方法的对照；需要生成式长程执行或生成器优化时另立合同，不默认搬入单步判定器 |

**数据覆盖由承诺能力决定。** 要服务长历史，就训练并评估真实长历史；要保留NONE、二元验证、评分、视觉或生成能力，就准备对应回归切片。只做固定choice的系统不必补造全部题型；“混题型”“长度完全一致”也不是所有任务的统一配方。可比较合适的replay／anchor，但不能从一个模型继承固定KL系数。

**不按算法名称永久排除。** GRPO／RLVR的特定正确性奖励可能破坏概率质量，但不证明所有奖励、估计器和底座都如此；RLCR、Brier或其他校准目标亦有各自部署对象。无独立收益证据时保持简单基线，有匹配问题时再做消融。使用Jev输出训练竞争模型存在明确条款风险，未取得适用授权时不把它设为默认教师；本指南未裁定任何第三方主体是否违约。[TypeSafe条款](https://typesafe.ai/legal/mca)

<a id="readout"></a>
### 读出、推理和参数化是不同维度

先看[两张神经网络结构图](../docs/landscape.md#architecture-deltas)，定位输入与mask、hidden读出、输出头及可训练参数；按固定版本验证，勿从统一API推断同一计算图。

| 选择 | 需要核查什么 |
|---|---|
| 固定分类头／候选token／pointer head／encoder评分 | 训练与服务的候选、分词、归一化、排序和截断是否一致；未知候选是否受支持 |
| 直接读出／先推理再读出／按需级联 | 实际返回哪个分布；额外prefill、生成、再读出、超时和回退均计成本 |
| LoRA／head-only／全参 | 哪些参数真的更新、是否保存自定义head、adapter是否已合并；推理可加载不证明反向可运行 |
| 温度或其他外部校准／权重训练 | 前者不更新主干；正温度保持同题argmax，但可改变ordinal期望和后续策略。字段、route与联合选择的校准对象不能混同 |

逐命题BCE须匹配Bernoulli／多标签读出；单个choice softmax不能同时表示多个动作都可能很高的成功率，其和受1约束，而各动作成功率之和可以大于1。

模型输出类型合法不等于事实正确；一次HTTP也不保证一个回合只进行一次模型工作。多个问题共用state、互不读取对方答案，不等于统计独立。若第二题候选依赖第一题结果，应显式实现序贯或联合合同，不能靠同请求叙述获得条件化。

### 第一轮具体比较哪些模型

首选算法内也要比较合适的模型实现：有复杂状态／条件组合、候选描述且标签较少时，优先试0.6–4B语义底座的LoRA＋简单读出；短输入、稳定标签、标签较充分且延迟极严时，多语encoder微调前移。冻结多语embedding＋正则化LR／小头可最先跑，等质量达标即可采用。现有新研究主要是英语，不证明中文长状态4B已胜过现代多语encoder。

<a id="pplx-v13-enterprise"></a>
### Perplexity Decider v1.3 27B：企业数据续训准入

2026-11-25核查的[完整native发布物](https://huggingface.co/perplexity-ai/pplx-decider-v1.3/tree/9c2ebb27470d3dec2ad7ab727727e40d142c7213)公开、ungated、Apache-2.0，原底座为Qwen3.8-27B。本节的“base”指**已经后训练的Decider检查点**，不是回到原Qwen随机重建决策头。结论是**值得优先做有界训练适配验证，但不是开箱可运行的企业trainer**。38个发布文件含推理、协议、fast与Locate代码，未定位v1.3完整trainer／loss／optimizer／数据构造闭环；v1.1带训练代码不代表能直接训练v1.3。

官方[技术报告](https://www.perplexity.ai/en-GB/hub/blog/perplexity-decider)披露通用全参、领域LoRA加权合并、视觉适配及Flash蒸馏；这支持把已学会决策合同的权重作为适配起点，不意味着企业必须重跑原作者全部阶段。效果和案例以[证据E47](../docs/evidence.md#e47)的作者报告边界理解；报告较详细，不据此宣称领域最完整、企业成功或普遍胜过其他底座。

**先冻结实际输出与执行合同。**

| 对象 | 该发布物的事实 | 企业适配要求 |
|---|---|---|
| 普通判断 | 默认`separate`为每题独立序列；`isolated`可共享state，但state看全部题，因此可经多层间接串扰 | 首轮从单题文本／`separate`合同起步；保存原分组以便后续比较，不把一次HTTP等同一次前向或统计独立 |
| 读出 | `joint_config.version=4`，每题`fim_suffix`特殊marker读出；独立255×5120头，候选答码及tokenizer固定 | 保留原权重、readout、processor、模板、marker索引、attention mask与有效K项；不能用v1.1末token模板或直接换成CausalLM完整词表头 |
| 注意力 | full层非因果；DeltaNet保持因果；separate／isolated／fast的计算不同 | 训练和服务在同一合同下对照；不靠模型名称假定通用Trainer能保留自定义mask |
| 校准 | 保存温度只是原数据拟合参数 | 训练loss用未校准logits；完成适配后在独立Cal-fit拟合，再在Cal-policy验证完整接受／转交策略，Test冻结确认 |
| Locate | 另有未合并LoRA、marker embedding及span头；混合请求需额外forward | 首轮若目标仅路由，关闭Locate；要保留抽取时，先保留原版Locate作为独立服务对照，再验证或重适配新的底座配对 |
| 加速／精度 | fast可改变少量近边界答案；Locate在fast下禁用 | 先用reference路径验收，再比较实际生产fast／量化／batch。概率差异可能改变执行门槛 |

**训练实现缺口是具体可定位的。** 固定[model.py](https://huggingface.co/perplexity-ai/pplx-decider-v1.3/blob/9c2ebb27470d3dec2ad7ab727727e40d142c7213/source/src/pplx_decider/model.py)将backbone/readout冻结并设eval；`reference_logits`带`@torch.inference_mode()`，结果转CPU普通列表。直接调用`Decider.logits()`无法作为反向传播loss输入。应新增薄的可微训练wrapper，复用已核协议编码与骨干／readout加载，返回marker位置的tensor logits，保留其计算图；不能只改requires_grad后继续走推理接口。

第一轮建议（设计建议，尚未实现或运行）：

1. **语言侧LoRA＋原255头冻结**作为受限适配臂；精确列出参与的full attention、DeltaNet与FFN投影，不照抄另一架构的q/v名单。纯文本任务冻结视觉模块及Locate，保留原head身份，不重置答码含义。
2. 使用可信硬标签或有依据的分布做候选内CE；另比较“同LoRA＋原head解冻”，确定冻结head是否限制领域增益。不要同时加入新数据、不同mode、Brier、多个教师和多次权重平均后归因一个算法。
3. 只有保留任务出现回归时，比较获授权的replay或原版分布KL锚定。旧模型与新政策冲突时，以核定新gold为准，不让锚定强迫保留旧错误。
4. LoRA合并系数可在Dev有限搜索，但合并不自动保能力；三seed soup、Flash蒸馏和视觉专项均非首轮必选。先验证27B适配净增量，才讨论压缩。

**不可遗漏的代码风险。** `isolated`依赖forward期间暂存的`isolation.layout`，推理后会清空；若增加gradient checkpointing而直接沿用该生命周期，backward重算可能失去原mask。须让layout在反向重算仍然正确或改为显式无状态输入，并对checkpointing开／关比较梯度和输出。这是静态发现的风险，不是本仓复现的失败。

Locate的`verify_base`核部分配置、readout及tokenizer哈希，并未认证全部backbone tensor；即使加载通过，也不能证明更新底座后原Locate仍兼容。不要把域LoRA与Locate LoRA直接叠加或合并后声称互不干扰。独立存储原checkpoint、新adapter、head状态、校准器和训练／部署配置；整模型或adapter导出都须重载复验。

**企业数据和算力是进入训练的前提。**

| 必须准备 | 最小可审查内容 |
|---|---|
| 单一目标 | 例如路由适用性或信息充分性，定义输入时点、候选、允许动作、关键错误代价与fallback；先核原版是否已达标 |
| 获授权的真实输入 | 决策前会话、必要状态和当时政策；标签可参考结果裁定，但未来事实不得进模型输入。输入分布应覆盖长状态、近似候选、无适用项和目标变化 |
| 标签语义 | 确定单gold、独立多标签或多解集合；choice概率不能当每动作独立成功率。硬标签不强制转teacher-soft；多解／缺证据不得随意伪造唯一答案 |
| 可信切分 | 先按客户／案件／会话／时间及近重复分组，再做增强；Train、Dev、Cal-fit、Cal-policy、Test职责分离，保留所有尝试与决策记录 |
| 保留能力合同 | 只承诺实际需要的题型、中文／多语、图片或Locate；准备相应回归切片，不默认保留整个原模型能力 |
| GPU预算 | 原生BF16主权重约49GiB，另需激活、梯度、优化器及adapter。LoRA仍驻留底座，full训练通常显著增加显存；不把能推理或某卡标称容量当可训练保证 |

**推进顺序与停止条件：** 固定native版本原版评测 → 对真实代表性batch核模板／marker及前向一致性 → 有限反向更新并验证非零有限梯度／loss → 保存重载和reference服务概率对齐 → 同数据比较原版、LoRA及必要解冻头臂 → 独立校准／策略验收 → 业务影子及有界对照。任何阶段不能保留原计算合同、关键错误恶化、总成本无收益或原版已足够，都应停止扩大投入。

当前完成的是官方证据、发布完整清单及静态源码审查；没有权重下载、企业数据、实际反向／保存重载、NVIDIA峰值或生产结果。通过上述准入后，v1.3才可从“值得工程适配的强候选”升级为“本项目已验证可训底座”。

**新增RL证据应按机制读。** [Drex v2](https://arxiv.org/html/2611.07854v2)的pointer RLAF直接求修正教师目标的proper loss梯度；Max则是有限动作期望奖励加参考KL。Max追加阶段有正结果，但缺等额继续SFT和训练种子控制；教师甚至可能压过verified答案，效用目标不自动给真实概率。[Mapika的闭环PPO说明](https://github.com/Mapika/decider/blob/91b6fa9b94ab6c4dc2c63d3b14d413243b4fffcc/docs/RL.md)也有执行成功正结果，却混合真实环境概率辅助任务／replay，采样、greedy与迁移表现不同。它们支持条件研究，不支持对静态客服直接替换成RL。[阶段记录](../docs/evidence.md#e45)

**标签歧义证据须核分母。** [工具选择审查](https://arxiv.org/html/2610.02267v1)的19.8%是全部400道hard工具题中79题被LLM判有其他有效工具，不是19.8%的模型错题，也非独立人工真值。它支持审查允许集合，不能证明教师soft比人工hard更诚实。该来源K50摘要还混用了完整80题与unique57题，比较应回到相同子群。

**避免把榜单当后训练选择。** StartLux的10月DI榜首是历史事实；11月19日[DI0.4.1固定汇总](https://huggingface.co/spaces/multimodalart/jev-decision-index/blob/4ee57a1610e0547634ba0ec11990d10122672191/data/v03.json)已非第一，且任务／权重／刻度改变。PPLX v1.2的68.09／58.88是public joint请求分数；它们都不能推出目标企业的适配赢家、数据效率或Mac可训性。

<a id="data-plan"></a>
## 4. 企业数据：先确定可学信号

一个标注单元是**案件在决策前的状态**，不是未来结局或任意一句聊天。保留如下字段及责任；具体JSONL要按所选trainer转换，不先设计跨项目共享平台。

| 数据组 | 最少内容 |
|---|---|
| 追溯 | 案件／会话／客户组ID、决策时间、来源与权利范围、政策／候选schema版本 |
| 当时输入 | 当前目标、必要历史、事实值及来源时间、unknown、owner、已执行动作及工具回执 |
| 决策合同 | 输出字段、候选、前提／依赖、允许集合、禁止动作及证据ID |
| 监督目标 | 人工／教师／规则来源、裁定和分歧；hard、soft、多标签或允许集合的语义 |
| 结果反馈 | 选中动作、日志策略及可用propensity、结果事件／窗口、后续干预、缺失／迟到和纠正 |
| 任务终态 | 正确完成及副作用断言、返工／再次联系等定义、实际费用和延迟范围 |

历史行为不自动是gold；优秀坐席也可能有多个合法动作。未来订单结果可以帮助裁定，但不能泄漏为当前输入。未知反馈不能填0，未加载工具不能造为负例；仅采集人工升级或已接受案件都会漏掉相应高置信错误或被抑制的有效请求。

**四类标签处理：**

- 明确、可信的单类标签可直接hard CE；不为显得先进强制软化。
- 独立命题／多意图用符合部署语义的多标签、允许集合或逐条件目标，不将多个都正确的动作硬凑为唯一类；集合监督也须说明怎样算整条决策正确。
- 可复核的真实分歧可保留分布；教师logit、口述confidence、重复采样频率和真实业务概率不是同一信号。教师需要独立审查一致样本和分歧样本。
- 缺信息、OOS、缺候选、政策冲突与目标撤销单列；均匀target可作实验正则，不等于已学会可靠拒判。

**切分先于增强。** 按客户、案件、会话、来源与时间分组；同案件的候选配对、翻译、改写与反事实样本同组。职责分别为Train更新权重、Dev选择方法／预算、Cal-fit拟合概率、Cal-policy选择完整接受／转交规则、Test冻结确认。可论证的交叉拟合是另一协议；共享校准样本的探索性扫描不能继承独立校准风险界。自然流量或已知抽样权重估计总体风险／费用，困难例与少数高损失错误单列。

数据构造优先覆盖相邻能力硬负例、最小事实改动、否定／例外、缺必要事实、多合法项、目标改变、新政策、长历史和无工具需求。Nimble式事实改动是数据因素，不是另一种底座或contrastive loss；控制数据量、标签频率和模板后才判断它有无增益。

<a id="input-format"></a>
**判断输入：分层组织，历史长度用实验定。** 原则是给决策前可见、且该判断真正需要的信息。建议五层：

| 层 | 内容 | 理由 |
|---|---|---|
| 当前消息 | 原文，不改写 | 判断的直接依据 |
| 最近 N 轮 | 用户与客服双方原文，带时间 | 指代、目标改变、已承诺事项多在近几轮 |
| 更早历史 | 结构化摘要：诉求、已完成动作、未完成目标 | 长原文噪声大、费 token、有位置偏差；JevRSI 消融显示结构化进度摘要优于原始轨迹（[P07](../problems/P07-state-and-action.md)） |
| 业务状态 | 系统事实，附来源与时间；未知显式写 `null` | 身份、订单、权益不从对话推断 |
| 问题与选项 | 键名加一句说明，版本化 | 说明措辞会改变结果 |

```json
{"current_turn":"上次那笔也退掉，别再扣费了",
 "recent_turns":[{"role":"user","t":"10:02","text":"我取消续费了吗？"},{"role":"agent","t":"10:02","text":"已为您关闭自动续费"}],
 "dialogue_summary":"用户先咨询续费状态，已关闭；现追加退款诉求",
 "case_state":{"identity_verified":false,"order":{"status":"paid","refunded":null},
   "completed_actions":["close_auto_renew"],"open_goals":["refund_last_charge"],
   "facts_source_time":{"order.status":"订单系统 10:01"}},
 "policy_version":"subscription-demo-v1",
 "question":"下一步应该做什么？",
 "options":{"verify_identity":"…","query_order":"…","refund":"…","clarify":"…","handoff":"…"}}
```

主数据集按此结构保存，训练视图由同一渲染模板生成；**训练与服务必须共用这个模板**。

历史窗口消融（Dev 上，同模型同标签）：①只给当前消息；②＋最近 3 轮；③＋最近 8 轮；④长度上限内的完整历史；⑤＋最近 3 轮＋摘要＋业务状态。除整体指标外，分报指代型、目标改变／撤销、多诉求、长会话切片；选达标且最短的一组后冻结。

注意：
- 只放判定时点前可见的内容，不放客服后来的结论、最终结果或回填标签。
- 长度上限因实现而异：Laya 约 1024；LemonDecider 每题 8192，超长拒绝；Kev 小型号验证到 8192；Unsloth 训练时超长会**截掉输入末尾**（最新一轮常在末尾），须把输入控制在预算内或把当前消息与关键状态前置。
- LLM 生成的摘要单独抽检；能从系统取的事实不靠摘要。
- 先脱敏再进训练集。

<a id="data-format-choice"></a>
**主数据集是正本，工具与论文格式都是视图。** 数据不按某个工具或论文组织，而是按上面的结构保存，再为每个实现写一个薄转换脚本。两类格式的差别：

| 维度 | Unsloth `state`／`questions`／`gold` | 论文或专用检查点格式（Kev、LemonDecider、Intern、SII、PRDO 等） |
|---|---|---|
| 问题分组 | 一行可含多题，联合头在一条序列里同时读 | 多为一行一题（LemonDecider 公开数据丢了原始分组）；Intern 用占位符多字段 |
| 渲染与读出 | 框架内部渲染，绑定 Clef 式联合头 | 模板与该检查点的读出合同强绑定（答码位置、标记、选项字母） |
| 标签语义 | choice 键、noul 布尔、score 下标；`probabilities` 给软目标 | 各自定义；如 SII loader 要求 `gold_target/train_target/p0` |
| 划分与校准 | 内置按行随机留出，并与校准共用 | 依论文协议，常不公开完整划分 |
| 适用 | 首轮对照、快速迭代、Mac 路径 | 复现某方法，或从该检查点续训 |

选择规则：首轮用 Unsloth 视图；要从某个专用检查点续训（如 Kev `--init_from`、LemonDecider），就必须用该检查点训练时的模板与标签合同，否则续训等于换合同；要复现论文方法（如 PRDO），按论文格式生成视图。无论哪种，划分、分组信息与校准都来自主数据集，不用工具内置的。多题分组信息要在主数据集中保留，联合训练与逐题训练才能对照。

**数据卫生与回放（参照 LemonDecider 的做法）：**
- **保能力回放集**：领域适配时混入一部分通用决策数据，防止窄覆盖造成其他题型退化。可用 LemonDecider-Decision-Mix，但必须先按 `row_licenses.jsonl` 过滤，先筛作者标为commercial的行（约66.2%），再核上游具体条款及授权范围；该分类是best-effort，不是许可认证。
- **卫生清单**：按来源设数量上限；跨来源去重；用评测样本指纹排查泄漏；检查答案泄漏和输入长度。服务端遇到超长输入应拒绝或显式拆分，不要静默截断。
- **Lemon的软标签来源规则**是只保留原标注分歧；这不是所有任务的禁令。经核验教师分布仍可作蒸馏目标，应与同批数据hard目标比较，不将教师分布当真实业务概率。
- **按模型弱点构造增量数据**：把经复核的错题及正确题的加难变体作为训练候选。仅从Train或声明的开发范围挖掘；Dev行一旦入Train须重新划定独立Dev，旧Dev分数失效，不能碰Cal或Test。
- **采集系统自己的轨迹状态**：模型在真实流程中犯错后到达的状态，静态标注集里没有，要从影子运行或回放中补采（JevAgentHarness 的做法）。

公共材料只用于对应诊断：[ABCD固定资料](https://github.com/asappresearch/abcd/tree/6b8700ce67c6b37b062dd7a60abc76d7ef832a97)可借流程／动作设计，但全会话subflow不等于每个可见前缀都可唯一识别；CLINC可测OOS／意图混淆，SGD-X可借描述变化，不能替代企业留出。[τ²固定评估合同](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/docs/evaluation.md)用于最终状态思想，版本、数据许可和模拟／真人边界分别保留。

<a id="method-views"></a>
### 一份主数据集，派生各方法的训练视图

不同方法的差别在三件事上：训练出的**输出合同**（决策头直接出概率、生成短标签、先推理再读出）、需要的**监督信号**、训练时是否**在线采样**。多数方法共用同一份核心标注（决策前状态、选项、gold），只是转换成不同的训练视图；真正需要额外采集的，只有教师分布、偏好对和带行为策略概率的日志。

| 方法 | 额外数据要求 | 推理形态 | 训练计算 | 现成实现 |
|---|---|---|---|---|
| 决策头 CE／独立命题BCE | 硬标签／分布／独立命题标签；允许集合须另定结构化目标 | 一次前向出概率 | 低 | Unsloth候选分布CE；独立命题可映射noul，任意多标签BCE需适配实现 |
| 教师 soft/KL | 经审核的教师分布 | 同上 | 低，另计教师推理 | Unsloth（gold 支持 `probabilities` 字段） |
| 生成式短标签 SFT | 无（标签写成文本） | 生成标签；序列概率须预先定义 | 低 | Unsloth SFT、MLX-VLM |
| GRPO | 可验证奖励（gold 即可） | 推理后作答 | 高，在线采样 | Unsloth GRPO |
| DPO/KTO | 偏好对或好坏标记 | 生成式 | 中 | Unsloth |
| PRDO | 无（不需要目标推理或置信度标签） | 推理后读出 | 高，每题在线采样多条推理 | [openjev-rlcd](https://github.com/ZimmyGao/openjev-rlcd/tree/5859d2b893314fb3581f06e4e36c303e372b3f48) |
| CAPS 等部分反馈 | 被选动作、结果、行为策略概率 | 决策头 | 低 | 无通用实现 |

Unsloth 是通用微调框架（SFT、DPO/ORPO/KTO、GRPO/GSPO、VLM 训练，以及 11 月新增的决策头训练，见[文档索引](https://unsloth.ai/docs/llms.txt)），不包含 PRDO。

主数据集每个决策点一行，字段按 §4 的数据组组织：追溯与分组 ID、决策前输入、决策合同、gold 及裁决记录、可选的教师分布／偏好对／日志反馈，以及**一次冻结的划分**（train / dev / cal_fit / cal_policy / test）。各训练视图由转换脚本从主数据集生成，例如 Unsloth 的 `state`／`questions`／`gold`、SFT 的对话格式、PRDO 和 GRPO 的“题目＋选项字母＋`Answer:`”提示、DPO 的偏好对。所有方法共用同一份划分清单和哈希，不各自重新切分。

## 5. 从第一性到实践：可勾选TODO

**第一性：** 在决策时可见状态`x`、候选`A`和判断标准下，用可信标签训练`pθ(y|x,A)`，再由业务规则和错误代价决定执行／补证／转交。概率模型、执行政策、权限检查是不同对象；训练loss下降不是业务目标达成。先选一项高频、可裁定的决策，不默认同时训练所有客服能力。

本清单用于学习与实施，尚未执行的项目保持未勾选。每步的产物放在真实实验所属项目；研究仓只保留公开协议与脱敏结论。任务自身需要多选时保留真实合同，不为了跑通示例把多个合法动作硬凑成唯一gold。

**A．理解：能解释一条样本怎样改变参数。**

- [ ] **01 定义业务判断。** 写一页决策合同：当时输入、允许候选、正确／多解／缺证据标准、错误代价、当前方案及拟改善的瓶颈。**通过：** 代表性样本能由标注者按同一准则裁定；缺政策／状态时先补证据。详[§1](#decision-contract)。
- [ ] **02 读懂实际模型。** 对照[结构图](../docs/landscape.md#architecture-deltas)，找到embedding、骨干、hidden、读出头、候选logits与概率；说明训练配方、Trainer、LoRA/full、loss／梯度／optimizer和校准各管什么。**产物：** 一张标出“保留／冻结／更新”的具体模型图，而不是只认模型品牌。
- [ ] **03 跟踪一条输入。** 用一条人工核对的合成例追踪完整模板、token／marker位置、候选ID、有效logits及target；手算单gold的`−log p(gold)`。**通过：** 能解释原模型如何出分，以及未来loss应更新哪部分参数。合成例只验证理解／接口，不当效果证据。

**B．证明值得训练：先有可靠数据与对照。**

- [ ] **04 建立获授权的数据与切分。** 抽取决策前状态，审核历史行为标签；补近似候选、无适用项、多诉求、目标变化及必要的长上下文。按客户／会话／时间及近重复分组，切分先于增强，分别安排Train、Dev、Cal-fit、Cal-policy和Test。**产物：** 数据说明、分组清单、标签裁决与泄漏检查；各组作用见[§4](#data-plan)。
- [ ] **05 跑不训练与廉价基线。** 比较现用系统、候选原版（含合理提示／候选说明及校准）和一个任务合适的简单监督方案。**通过：** 在开发数据上定位可学习的剩余错误，并预定关键风险、最小有用收益及总预算；原版已达标可停止训练。Test此时封存。
- [ ] **06 选一个可实施起点。** 固定检查点、代码、许可、tokenizer／processor、head和模式；检查Trainer是否支持原生续训，有无图像／长度限制。**产物：** 版本与硬件清单、缺口清单及预算上限；原始Qwen加新头与专用决策检查点续训分别命名。模型少量入围即可，不重复扫榜。

**C．实现：先证明梯度和保存是对的。**

- [ ] **07 接通可微训练链。** 优先复用符合模型合同的trainer；没有就补data collator、tensor前向、有效候选loss、LoRA／optimizer、保存恢复。**通过：** 未更新参数时，训练wrapper在eval模式与官方reference前向对齐；dtype／容差事先声明。Perplexity专项见[原生v1.3准入](#pplx-v13-enterprise)。
- [ ] **08 做最小训练冒烟。** 在代表性短／长batch上检查有限loss、预期参数非零有限梯度、冻结权重不变、有限更新、峰值显存和保存重载；需要时尝试过拟合一个极小训练子集来排错。**通过：** 可复查运行回执；少量loss下降／小样本过拟合仅证明工程行为，不证明泛化。
- [ ] **09 做第一轮受控领域适配。** 有可信互斥标签从CE起步，独立命题用匹配的BCE或逐Noul合同；多解集合另设目标。按资源选LoRA／小头／full，先跑一条简单路线；在Dev选学习率、更新预算等并记录全部尝试。**产物：** 与同一原版对照的学习曲线、分组错误和资源记录；不规定统一400步、rank或样本量。只在有理由时增加重复seed和消融。

**D．验收：工程正确、预测有效、业务有用分别证明。**

- [ ] **10 校准并冻结完整策略。** 用独立Cal-fit拟合适当概率映射；Cal-policy选择接受／补证／转交规则，计入回退对象的错误及费用。**通过：** 冻结模型、模式、概率映射、阈值及回退；小样本和分布漂移不自动获得风险保证。多字段联合动作按整条策略验证。
- [ ] **11 独立Test与部署复验。** 同一测试比较原版和适配版的关键错误、分类／允许集合质量、NLL／Brier、风险—覆盖、完整延迟／成本及保留能力；给配对不确定性，计超时／无效输出。验证重载、merge、量化或fast路径的实际部署分布。**通过：** 达到预定业务标准；测试一旦用于调参就变为开发历史，需新验收集。
- [ ] **12 进入业务并按失败迭代。** 先影子运行与盲审，再有界对照、回滚与结果成熟窗口；检查完整会话成功、副作用、人工及返工成本。**通过：** 实际任务增量成立。标签缺口才加教师，服务成本瓶颈才考虑小模型蒸馏，保留推理且有净价值才研究PRDO，真实反馈合同成立才研究RL／CAPS。原版达标、无净增益或关键风险恶化时停止扩大投入。

**每轮最少交付六样：** 决策合同、版本化数据／split、固定配置、可运行训练／评估入口、模型与adapter／校准产物、含负结果和下一步的对照报告。前三步建立理解，第07–08步证明工程，第09–11步检验统计增量，第12步确认业务价值；不可用一层通过替代另一层。

第一轮实际比较：冻结多语embedding＋简单头、多语encoder监督、0.6–4B LoRA监督（含原版；通过资格检查后可用Unsloth `DecisionTrainer`实现，自行提供分组划分和独立 Cal／Test）；按业务特征先保留其中少数组合。第二轮只对剩余标签／覆盖缺口加入经核验教师，固定保留样本后比较hard与soft。不默认“教师soft→训练27B→4B→每周CAPS→PRDO”。教师已够好可直接产标签；小模型直接达标则不必付教师训练费。若转交率为q，级联还要支付首阶段、转交子集的强模型、重试及人工等成本；强模型总体accuracy高，不保证在被转交的样本上更好。[级联对照](https://arxiv.org/html/2610.00346v2#S5.SS3)

<a id="prdo"></a>
### PRDO 的实施方式

只在生产本来就保留推理、并按推理后的概率决定接受或转交时启用；零生成路由不需要它（见 [P03](../problems/P03-read-or-reason.md)）。

- **机制**（[论文 v2](https://arxiv.org/html/2609.38850v2)、代码 README）：每题从当前模型采样 M=4 条推理；在每条推理后的 `Answer:` 位置读出选项分布 u；对**每条推理各自**的 u 计算 proper score（Brier：`2u_y − ‖u‖²`；log：`log u_y`），并加参考 KL（主阶段有效的token KL参数为`--kl-tokens 0.01`；`--no-score-function`下`--kl-beta 0.04`不参与该阶段loss）；主路径不对推理 token 做 REINFORCE（`--no-score-function`）。
- **为什么不是 GRPO**：对固定状态、有限答案及只按正确性奖励的目标，期望效用倾向集中概率于最优动作；这不鼓励校准，但不是所有GRPO奖励、KL约束和训练配置都不能产生可用置信度的证明；对多条推理的平均分布打分，又会奖励推理之间的分歧，而该论文部署时单次请求只看到一条推理。若部署明确返回多条推理的平均分布，则应匹配该对象训练与校准，mixture目标并非普遍错误。
- **数据**：主数据集的生成式提示视图。选项要映射到单个 token，用实际 tokenizer 核对。
- **底座**：会生成推理的模型（如 Qwen3 系列）；决策头模型不适用。
- **代码**：官方 openjev-rlcd（CUDA）。另一种思路是在 Unsloth `FastLanguageModel` 上自写 loss：不求梯度地采样推理，再把“提示＋推理＋`Answer:`”整段前向，取选项 token 分布计算 Brier 与 KL。这只是实现思路，没有现成代码，也未验证。
- **资源**：论文每次运行用 48GB Ada，另需 125GB 主机内存。原实现为CUDA；缩至0.6–1.7B也不证明兼容MPS／MLX或能容纳。优先在兼容GPU验证；Mac移植需另验采样、反向、参考模型及完整内存。
- **对照**：先保留论文的direct-answer SFT（空推理）＋TS及GRPO＋TS；reasoning-SFT＋TS是本项目可新增的对照，需额外推理监督并计入数据／计算预算；同时报告准确率，因为 PRDO 在部分任务上准确率会下降（[E40](../docs/evidence.md#e40)）。

<a id="mac-feasibility"></a>
### M5 Pro 48GB：训练准入，不作内存／耗时承诺

- 固定模型与代码revision、Python／框架／算子、精度及完整输入分布。先跑含代表性最长状态／候选的真实前向和反向，再测少量更新；记录峰值、swap、跳过样本、梯度有限性和失败。
- 检查head或特殊marker是否实际被训练、候选顺序是否映射正确。保存adapter／head／tokenizer／schema和校准，重载后对同批输入比较概率与最终判定；服务端不能悄悄改模板或截断。
- **Unsloth 有 Apple Silicon 训练路径**（`decision_mlx.py`，基于 unsloth-zoo 的 MLX）：有LoRA与非量化full_finetuning分支，4-bit训练限LoRA；可从受支持普通LM新建联合头。源码测试包含保存重载一致性断言，不能当真实底座或目标机运行回执。它是本轮确认的Mac训练实现候选，具体架构、图像路径、依赖与M5容量须实测。[MLX 实现](https://github.com/unslothai/unsloth/tree/8b7cde79ebf5a901b2fd936bbee214fb8c7562c7/unsloth/models/decision_mlx.py)
- Kev有MPS分支但目标机backward未验证；SII公开wrapper用多GPU，已核LoRA发布为合并BF16独立权重、训练器另存adapter；Intern当前CUDA全语言训练不能按推理内存估算。改成MLX／LoRA是新实现，须重新验合同。
- 新增Strands v2／RSI训练代码仍以CUDA为路径，Jeff当前仅CUDA／CPU；Valen native续训已公开，但其设备上float64统计是MPS兼容阻碍；Liquid、RSI量化及Decisio的MPS／MLX推理包不构成Mac后训练证据。Strands E2B的2.3B有效参数、MoE的active参数和adapter文件大小都不能代替完整驻留／反向内存。
- 27B BF16仅权重通常已超48GB；量化教师推理与27B训练是不同任务。PRDO论文每run用48GB Ada，**另有125GB主机内存**；CPU offload不能给48GB统一内存凭空增加容量。[PRDO实现](https://github.com/ZimmyGao/openjev-rlcd/tree/5859d2b893314fb3581f06e4e36c303e372b3f48)
- 首轮数据量、更新预算、学习率、LoRA范围／rank、batch与停止规则先在Dev和资源预算内冻结；不抄400步、某个学习率或某张H100的美元数作保证。没有目标机receipt就写未测。

实际权重训练沿用工作区既有`improve/post-training`入口；企业数据、业务runtime及发布责任归实际业务项目。当前仓库维护知识与公开证据，不收原始客户会话、私有训练输出或企业凭据，也不新建空实验工程。

## 6. 验收：完整策略和真实任务

| 层次 | 必报指标／对照 |
|---|---|
| 决策质量 | 意图／条件／路径指标、允许集合与关键误触发／漏判；无效输出、超时和回退不剔除 |
| 概率与选择 | 明确口径的NLL、Brier、ECE及风险—覆盖；分母、分箱、失败处理和阈值选择组写清 |
| 鲁棒与退化 | 顺序、同义条件、相似工具、缺候选、unknown、OOS、过期事实、撤销／多诉求、长输入及来源／语言／政策漂移 |
| 完整交互 | 正确完成、禁止副作用、无效澄清／重复联系、人工复核与返工；更换动作后的结果需完整交互验收，静态日志不提供反事实终态 |
| 完整成本 | 标注、教师、训练／调参、检索取数、冷暖推理、重试工具、人工及修正；在真实长度／并发／cache下记录p50／p95 |
| 不确定性 | 同案件配对、按客户／会话等独立组估计区间，种子不替代新增案件；预定非劣界／有用增量和多重选择规则 |

**“只允许5%错误”和ECE不是两项足够的终验。** 5%只是可选业务预算，关键错误可能需要另设约束；测试标签上挑出的最大可接受前缀是oracle，不是上线阈值。正式风险控制有固定评分器、独立数据、抽样／交换性等具体假设；漂移后需重新确认，理论proper目标或NONE选项都不单独提供保证。

温度要对实际返回的对象拟合：argmax直接读出、推理后读出、融合结果和级联返回可能有不同校准。按题型温度可以比较，但不能替代route／字段／完整选择策略的验证。[StartLux v2的策略校准](https://arxiv.org/html/2610.17309v2#S5.SS5)和[校准基础](https://proceedings.mlr.press/v70/guo17a.html)说明两者边界。

两个问题的选项互不依赖，也不自动给出联合正确率。即使在同一接受子集上两问真实边际均.95，独立时联合正确仅.9025；实际也不能假设独立。用案件级Cal-policy验证整个“意图＋动作＋约束”的规则，不能把两个自报置信度相乘就当风险证书。

<a id="unified-evaluation"></a>
### 统一评测协议：不同方法放在同一张表上

先固定业务终点和允许动作／集合，在同一冻结Test比较完整策略；只有概率事件、候选及归一化语义一致时，才横比NLL／Brier。独立命题BCE、互斥choice、多解集合和生成序列并非同一分布。条件有四个：

1. **评估实际用来决策的那个分布**：决策头取输出概率；生成式短标签按预先定义的序列概率；PRDO 取单条推理后的读出，不取多条平均。
2. **统一校准程序**：在同一个Cal-fit上按输出合同拟合合适的概率映射（单温度并非都适用），在同一个 Cal-policy 上选阈值，Test 只看一次。Unsloth内置两半交叉拟合报告仍非独立业务验收，应使用分组Cal-policy及Test。
3. **成本单独报告**：本实验保留生成推理的GRPO／PRDO臂每次请求需生成（有限动作GRPO不必生成文本），延迟和 token 成本显著高于一次读出，须实测完整请求的 p50/p95 与单次决策成本。等更新步数不等于等算力。
4. **划分只做一次**：按客户、会话、时间分组；种子波动单独报告，不当作独立样本。

推进顺序：第一轮只比较冻结embedding＋小头、多语encoder、通过准入的决策头LoRA，三者都只需主数据集；第二轮仅在剩余错误来自标签缺口时加入教师 soft，与 hard 对比；第三轮只对保留推理的子任务比较 GRPO＋TS 与 PRDO。每轮输出同一张评分表，对照预注册的最小收益与关键风险上限决定继续或停止。

<a id="routing"></a>
**路由结构与技能加载只在它们是瓶颈时比较**（完整方案见 [skill 路由选择器](skill-routing.md)）。 选项数、描述预算和可靠外部域信息决定是否试flat、检索、多候选或分层；Jev的层级.673是404／600联合正确，gold域细分另为567／600。显式NONE与外部gate等是候选机制，须同时测OOS误接受、域内覆盖与漏判。按需加载另固定判断器／执行器，分别测候选召回、实际加载、遵循、执行和任务终态；依赖闭包或状态新鲜度不能由top-k命中代替。

<a id="production"></a>
**生产推进：** 冻结配置后先影子观察，盲审分歧也抽查一致／高置信自动接受及被抑制案件；再做有界对照、停止／回滚和结果成熟窗口。概率门槛不授予权限，执行回执与真实结果分别记录。离线分数提高而任务成功下降时，检查状态、工具、候选、策略和评测等原因，不能只调严阈值或拆细动作。

学习闭环由反馈质量和漂移触发，不按周自动重训。只有日志定义和支持满足条件，才研究CAPS等部分反馈；多动作均可能成功、延迟与干预显著时，需要不同结果模型／识别合同。没有解决真实失败、未胜过便宜基线或完整成本无收益时，保留负结果，停止扩大投入。
