# Skill 与路径选择器：动态加载的训练与验收

更新：2026-11-21。场景：企业服务 Agent 覆盖约 40 个技能或流程，每轮先由选择器（loader）选出一小组技能，再交给执行器。本页只写怎么做。“为什么这样做”见 [P08](../problems/P08-skill-loading.md)；选择器的训练沿用[通用流程](decision-pipeline.md)。

现状：方案就绪，没有运行过；只有 8 条虚构的合同示例。

<a id="design"></a>
## 1. 架构与设计原则

```
用户轮次 → 检索召回(top-k) → 状态谓词门控(代码) → 选择器判断 → 执行器(+ 常驻核心)
                                      ↓ 都不匹配
                               扩大检索 / 澄清 / 转人工
```

1. **先定技能粒度**：由业务负责人在标注前确定并冻结。它对结果起主导作用，优先于选择哪种加载技术。
2. **常驻核心**：红线、升级规则、身份核验、隐私处理由代码强制，不随路由加载或卸载。
3. **状态谓词门控**：每张技能卡写明前置条件（权益、订单状态、已生效设置）。前置条件不成立的技能直接剔除，不需要模型调用。
4. **必须有回退路径**：没有“都不匹配 → 扩大检索或转人工”路径的路由系统，从结构上就是脆弱的。
5. **成本按实际计费算**：前缀稳定时，提示缓存会抵掉一部分 token 节省，而动态加载可能破坏缓存复用。

技能卡至少包含：一段描述、处理流程正文、工具白名单、前置条件（门控谓词）、相关红线规则的链接。

<a id="training"></a>
## 2. 选择器的训练

**标签合同**
- 标注单元是决策前可见的对话状态（见[通用流程 §4](decision-pipeline.md#data-plan)）。
- 金标是**可接受的能力集合**：可能有多个可接受集合，每个集合内部是“且”的关系。不要硬凑成唯一类。还要标出金标技能是否存在于技能库中。
- 禁止动作在整段对话层面检查，不只针对路由标签。
- 示例：[skill-loading-cases.jsonl](assets/skill-loading-cases.jsonl)（8 条虚构案例，政策 `subscription-demo-v1`，只用来说明字段）。

**数据构造**
- 查询来自真实用户轮次，或由独立人员撰写。技能作者自己写的查询会让 hit@5 虚高 21–44 个百分点。
- 对易混技能对（例如“注销账户”与“取消订阅”、“退款”“取消”“降级”三者）、话题切换、多诉求、目标撤销做过采样；压力集单独报告。
- 困难负例：删去金标技能，用近似技能作干扰项（见 [E20](../docs/evidence.md#e20)）。
- 当时未加载的工具不能当作负例；只采集人工升级的案件，会漏掉高置信的错误。
- 训练、开发、校准、测试按会话和时间隔离；两名标注员独立标注并裁决分歧。

**委托与阈值**：JevAgentHarness 发现，不拟合阈值就把工具选择交给决策模型，任务成功率下降 19.0 个百分点；按每个决策点、在系统自己的轨迹上拟合置信阈值，低于阈值交给 LLM，才能在少量损失下大幅降本（[2610.21412](https://arxiv.org/abs/2610.21412)）。选择器上线前，在独立Cal-policy上比较全局与按决策类型分组的完整门控；少样本类别可共享或收缩阈值，避免逐技能过拟合。该论文不证明每个技能都应另拟阈值。

**候选选择器（同一数据、同一协议比较）**

| 组 | 方法 |
|---|---|
| R0 | LLM 从全部 K 个技能中选 |
| R1 | 先读元信息的渐进式披露 |
| R2 | BM25＋嵌入检索 |
| R3 | R2＋每个技能的离线意图查询 |
| R4 | 类型化决策模型（托管或 LoRA 适配），选项中加“都不是／升级” |
| R5 | 小型监督分类器（**基线**） |
| R6 | 两级路由：先类别，后技能 |

例如合法下一步为集合{A,B}或{C}，不能把{A,B,C}当金标；可枚举合法动作包做choice，或设计保留依赖／互斥约束的结构化目标，并按完整集合验收。

R4 和 R5 的训练按[通用流程 §2](decision-pipeline.md#method-selection)的优先级：先做直接监督（CE/BCE），独立多标签可用BCE；多个可替代集合需显式集合合同，不能把各集合并集一律标正；教师只用来补标签缺口。

**指标**
- 主指标：**recall@k**（漏检率），按带回退路径的方式计算。
- 风险—覆盖与 AURC；金标缺失时的错选率与金标存在时的误拒率，分开报告。
- ECE **和**正确性 AUROC；p50/p95 延迟；每千次路由的成本。
- 阈值在校准集上用 Learn-then-Test 拟合，在留出集上报告。

<a id="experiment"></a>
## 3. 预注册假设

| 编号 | 假设 | 证伪条件 |
|---|---|---|
| H1 | 全量暴露下，top-1 随技能数 K 下降；同等 K 下，易混库比差异库下降更陡 | K=40 时斜率差异不显著 |
| H2 | 限定加载器（k=5）在 K=40 易混库、独立撰写的查询上达到 recall@5 ≥ 0.98 | 没有任何加载器组达到 |
| H3 | 端到端，K≈40 时理想路由比全量暴露的 pass^4 高 ≥5 个百分点 | 配对差 < 3 个百分点 |
| H4 | 开启提示缓存后，路由的计费成本优势不到其 token 优势的一半 | 计费比 ≈ token 比 |
| H5 | 话题切换对话中，带滞后的逐轮路由优于按会话一次路由和无记忆的逐轮路由 | 无差异或结果相反 |
| H6 | 状态谓词门控减少对被拦截技能的选择，且不降低任务成功率 | 成功率下降，或被拦截的选择没有减少 |

## 4. 分阶段实验（由便宜到昂贵）

**阶段 1：只测路由，用公开替代数据**（本地，只有分类调用）
- 技能库：ABCD 的 55 个子流程转为技能卡，K ∈ {10, 30, 55} × {差异库, 易混库}；易混干扰项是近重复改写，加上 SGD 同类服务；中文部分加入 MASSIVE zh-CN。
- 拒判样本：CLINC 域外样本，以及删去金标构造的困难负例。
- 每格约 1,000 条，按对话聚类做配对 bootstrap，组间用 McNemar 检验。
- 停止：K=55 易混库上没有任何组达到 recall@5 ≥ 0.98 时，先重新设计粒度或加回退路径。

**阶段 2：只测路由，用企业对话**（私有，离线）
- 约 1,500 轮，按类别分层，并对易混对和话题切换过采样；自然流量的校准和测试集另外保留。
- K ∈ {10, 20, 40}，跑与阶段 1 相同的各组。这是对 H1、H2、H6 的未污染中文检验。

**阶段 3：端到端，模拟用户**
- τ 风格任务，配模拟工具和数据库状态；先在合并后的 τ-bench 领域上调通评测框架。
- 对照组：
  - 全量暴露；
  - 全量暴露＋缓存（只用于成本比较）；
  - 理想路由参考：逐轮提供经独立标注的完整必要技能集合；
  - 最佳加载器（k=5）＋门控＋常驻核心；
  - 去门控；
  - 去滞后；
  - 渐进披露；
  - A/A（全量暴露跑两次）。
- 指标：pass^4、政策违规率、每个已解决任务的计费成本、失败归因（加载器还是执行器）、目标切换后的恢复。
- 300 个任务 × 4 次是初始预算；先用 pilot 估计任务间相关性，再做功效模拟决定样本量。
- 停止规则：
  - A/A 波动超过（理想 − 全量）的一半时，先修评测框架；
  - 理想 − 全量 < 3 个百分点，且计费成本收益 < 20% 时，只能以治理理由决定是否采用；
  - 路由效率 η =（路由 − 全量）/（理想 − 全量）< 0.5 时，回到阶段 2。

**阶段 4：影子运行，然后灰度**（生产环境，需另获批准）
- 影子运行：与现有分类器并行，抽样分歧样本人工复核，每周检查漂移。
- 灰度：约 5% 流量；升级率、投诉率或红线触发任一超标，自动回滚。
- 每次更换模型、服务链路或校准器后，重新验证阈值。

## 5. 结果与行动

| 观察 | 结论 | 行动 |
|---|---|---|
| H2、H3 成立，η ≥ 0.7，验收达标 | 动态加载提升质量，路由器拿到了大部分可得收益 | 采用“路由＋门控＋常驻核心”，进入阶段 4 |
| H2 成立，H3 不成立，H4 显示真实计费节省 | 收益在成本，不在质量 | 业务量下节省有意义时才采用；保留“全量＋缓存”作为回退 |
| H3 不成立，且没有成本收益 | 瓶颈在技能内部的执行质量 | 不为质量而做动态加载，投入转向流程、工具和验证 |
| 易混库上 H2 不成立 | 原因未明 | 分层诊断标签、证据、候选召回、模型、粒度，按已证实的原因修复 |
| R5 ≥ R4 | 不需要决策模型 | 用本地小分类器；技能分类变化时再评估 |

## 7. 仍需人决定的事

技能分类与粒度；误路由与升级人工的相对代价（决定风险—覆盖曲线上的工作点）；常驻核心包含哪些内容；金标标注与上线决策。
